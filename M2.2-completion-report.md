## 2. Scanner architecture

`ProjectScanner` revalidate canonical target bằng Foundation, giữ identity của root theo device/inode và khởi tạo bounded reader cho request. Pha discovery ưu tiên root, declared members rồi duyệt breadth-first để thu inventory và boundary candidates. Pha detection chạy theo boundary đã xác định và hợp nhất facts theo evidence. Registry dùng các module tĩnh, mỗi detector có thể khai báo candidate file, discovery hook và detection hook. Fixture đăng ký detector mới trên core hiện tại và thu được fact riêng.

Typed subscription dùng `defineSubscription`, `server.handle`, `ctx.signal` và `ctx.push` của SDK 0.17.4. Input strict gồm `requestId` và `canonicalDirectory`. Daemon chỉ gửi một terminal result cho mỗi request còn kết nối. Consumer release subscription khi nhận result hoặc khi không còn quan tâm. Release/disconnect hủy công việc hợp tác; dispose abort các request và đợi cleanup. Không có cache giữa scans, custom cancel RPC, test-only RPC hoặc Scan UI.

## 4. Workspace và boundary behavior

Hỗ trợ `package.json#workspaces`, `pnpm-workspace.yaml`, `lerna.json#packages`, `go.work use` và `angular.json#projects`. Member path nằm trong canonical root. Matcher hỗ trợ literal, một wildcard trên mỗi segment và recursive `**` theo segment, với exclusions. Unsupported patterns trả warning. Tên thư mục hoặc package khác không tự tạo membership.

Nested app vẫn có boundary riêng khi không thuộc workspace. Dependency thuộc nơi khai báo. Angular project chỉ tham chiếu các khai báo Angular từ workspace root khi project được xác nhận trong `angular.json`. Không áp dụng root dependencies cho mọi member. Git root, worktree và non-Git dùng cùng pipeline. `.git` chỉ là marker presence/type, không được mở hoặc resolve ra ngoài target.

## 7. Security, privacy và resource limits

- Revalidate canonical root, kiểm tra device/inode, lstat từng path segment, so sánh canonical path, từ chối symlink/junction và mount con khác device. Regular file còn phải có đúng một hard link. No-follow và nonblocking open được dùng khi hệ điều hành hỗ trợ. Đối chiếu lstat/fstat trước và sau đọc. Controlled replacement của root, ancestor và file đã qua fixture, gồm ca thay ancestor mà directory ngoài target không bị đọc entries.
- Allowlist content reads và prune dependency/build/cache directories cùng secret files. Tests instrument `opendir`/`open` để xác nhận forbidden files chưa được mở, đồng thời dùng secret trong trường manifest để kiểm tra projection. Scan dùng Node filesystem APIs, không chạy command, install, thực thi config, tạo agent, ghi project hoặc gọi external service.
- Depth 6 bình thường và 10 cho declared members, 256 directory listings, 8.000 observed entries, 64 boundaries, 256 file reads, 128 KiB/file, 8 KiB/prefix, 4 MiB tổng bytes, 8 giây cooperative deadline, 256 KiB response, 64 warnings và hai lượt đồng thời mỗi installation. Các case malformed, permission và budget giữ partial evidence. Result vượt response budget ưu tiên giữ boundaries và refs khớp với chúng.
- **Giới hạn local-first.** Node pathname APIs không bảo đảm chặn tiến trình đối nghịch thay ancestor rồi khôi phục trong cửa sổ giữa hai filesystem calls. Deadline hợp tác không ngắt syscall đang chạy. Config executable, lockfile contents và provider activation nằm ngoài bằng chứng v1. PHP prefix discovery kiểm tra file cấp root, direct WordPress plugin directories và nested bootstrap theo tên; entry file tùy ý ở các thư mục khác có thể chưa được nhận diện. Workspace patterns ngoài tập hỗ trợ cần fixture trước khi mở rộng.
