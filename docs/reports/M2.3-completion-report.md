## 3. Shared executor và preflight

Một `AgentExecutor` nhận public `PaseoApi` đã bind tới host và thông tin profile từ server-side caller tin cậy. Registry tách availability khỏi `unverified`, `blocked`, `synthetic-eligible` và `production-eligible`. Profile khớp host, Paseo version, provider/version, model, mode, execution profile ID và purpose. Draft selection từ UI không tạo agent. M2.3 không ship approved profiles hay mở RPC submit prompt hoặc đăng ký profile.

Sau profile gate, executor kiểm tra explicit model và mode qua `providers.waitForReady` trong temp cwd. Codex yêu cầu `read-only`, `approval_policy: "never"`, search disabled và native schema đã verified. Cursor yêu cầu model trùng current model đã audit, đồng thời model được catalog đánh dấu default. Host hook conflict chặn Kiro kể cả có matching approval record. Antigravity và các mode auto-approve bị chặn theo guard. Không tự đổi provider/model, credentials, provider defaults hoặc mode host.

Executor dùng dedicated background directory workspace, xác nhận workspace ownership, sau đó tạo một agent. Codex gửi schema ở initial prompt và kiểm tra snapshot cùng kết quả; ACP tạo agent idle rồi kiểm tra model/mode thực tế trước `run`. Nếu runtime báo model khác hoặc không chứng minh được model effective, request thất bại. Không chạy agent trong project workspace. Không dùng internal daemon API.

## 4. Input/output contracts và privacy

- Internal request gồm `requestId`, host ID, explicit provider/model/mode và payload. Synthetic chỉ chiếu nonce. Production chiếu catalog SHA và ID/name/description, facts, boundary aliases, skill inventory tối thiểu, coverage và evidence reference aliases. Canonical target path chỉ dùng local để kiểm tra placement. Không gửi raw source/manifest/rules, filesystem paths từ evidence, script commands, supporting files hoặc credential fields.
- Instruction và Zod output schema do caller nội bộ sở hữu. Untrusted project evidence và descriptions chỉ được serialize trong dữ liệu JSON. Projection reject một số marker nhạy cảm trong descriptions. Marker checks không phải secret scanner tổng quát; production vẫn cần chủ động duyệt payload và profile. Prompt instructions không enforce permissions.
- Output chỉ dùng final `lastMessage` khi turn báo `idle` và ownership, model, mode hợp lệ. Parse một JSON document hoặc một JSON fence duy nhất. Không trích JSON từ prose. Dùng Zod kiểm tra closed object shape và từ chối output bị strip/transform. Cap 16 KiB trước parse; cap này áp dụng tại plugin, không phải provider token limit. Payload prompt tối đa 48 KiB. Không retry mặc định và không có semantic recommendation validation trong M2.3.

## 5. Permission, lifecycle và cleanup

Temp path có quyền riêng, kiểm tra nằm ngoài canonical target khi có target, không copy files vào đó và không truyền target cwd cho agent. Temporary cwd chỉ giảm dữ liệu workspace mà provider tự nạp. Production guard còn yêu cầu attestation deny permissions, không truy cập target, shell/network/extra tools bị chặn, host hooks an toàn và preferences không đổi. Các attestation chỉ do host caller đã xác minh cung cấp. Executor không approve tool calls; permission-required trả lỗi và cleanup.

Discovery, create, turn và cleanup grace lần lượt có deadline khởi điểm 15, 20, 45 và 15 giây theo từng pha. Abort và dispose chặn prompt tiếp theo và suppress output cũ. Cleanup đợi ACK đến muộn, dùng exact workspace/agent IDs và ownership nonce để đối soát, archive agent rồi archive dedicated workspace. Chỉ xóa temp sau archive ACK và xác nhận identity còn khớp. Mismatch hoặc không có ACK trong grace trả `cleanup_failed` với operation receipt và giữ tài nguyên cần đối soát. Cleanup đã khởi động tiếp tục trong process nếu ACK đến muộn. Không retry request có trạng thái chưa rõ.

M2.3 kiểm thử `dispose()` trực tiếp. Entrypoint hiện tại không giữ executor khi chẳng có execution route nào. Khi M2.4 nối caller, lifecycle của caller phải sở hữu executor và gọi dispose từ plugin cleanup. Hard kill có thể cắt ngang reconciliation, và archive không xóa history có thể đã lưu bởi Paseo/provider. Dedicated workspace dự kiến chỉ được executor sử dụng; SDK archive có thể cascade với agent/terminal thuộc workspace đó.
