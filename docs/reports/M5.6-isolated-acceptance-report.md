## 2. Confirmed Defect Fixes Implemented

### P7-A & P7-B — Shared Deterministic Operation Freshness
- Implemented `shouldAcceptOperation()` and `shouldAcceptSummary()` in `client/apply-tracker.ts`.
- **Same-phase summary freshness (P7-A):** `shouldAcceptSummary()` rejects same-phase summaries with older `updatedAt`, regressed `targetMutated` (`true` → `false`), or regressed `durability`, and never overwrites a full `ApplyOperation` at equal or higher phase rank.
- **Same-phase ledger progress semantics (P7-B):** `shouldAcceptOperation()` evaluates monotonic per-destination ledger state progression (`not_attempted: 0` → `created_incomplete / observation_changed / ownership_unknown: 1` → `unchanged_verified / created_verified: 2`) rather than assuming byte counts alone establish freshness. Any per-destination state regression or lower `(attempted, verified, rankSum)` tuple is rejected.
- **Coordinated `lookup` / `check` / `submit` / `ingestDiscovered`:** `lookup()` now registers a request token in `statusRequests`, discards superseded responses, and applies `shouldAcceptOperation()` before mutating state. Terminal full operations are protected against conflicting terminal overwrites while legitimate daemon-restart transitions (`writing` → `recovery_required`) and lazy ledger hydration remain allowed.
- **Preserved M4 invariants:** Synchronous tracking-before-submit (`tracking_unavailable` fail-closed) and existing `localStorage` format are unchanged.

### P8-A & P8-B — Bounded Asynchronous Journal Discovery
- **Bounded directory iterator (P8-A):** `ApplyJournal.list()` uses `fs/promises.opendir()` with sequential `dir.read()` capped at `limits.maxDirectoryEntries` (`256`), setting `truncated = true` and breaking immediately when additional entries exist without allocating or sorting unbounded directory arrays.
- **Bounded sequential async I/O (P8-B):** Reads records sequentially (no unbounded `Promise.all`) via `fs/promises.open(path, O_RDONLY | O_NOFOLLOW | O_NONBLOCK)` + descriptor-based `handle.stat()` + `handle.read()`, enforcing `isFile()`, `nlink <= 2`, owner UID, `0o600`, per-file (`2 MiB`) and total (`16 MiB`) byte budgets before `Buffer.alloc`, and pre/post `checkDirectoryAsync()` `(dev, ino, uid, mode, realpath)` validation. Strictly read-only (zero writes, unlinks, or fsyncs).
- **Bounded concurrency:** `createDiscoveryConcurrencyGate(2)` bounds simultaneous `apply.list.v1` scans per plugin instance and fails closed with `{ status: "error", code: "busy" }` when exceeded.
- **Mid-scan trust revalidation:** `listJournalSummaries()` revalidates `verifyTrust()` both before starting and immediately after async journal I/O completes; if Relay opt-in is revoked mid-scan, the RPC fails closed with `unsupported_environment`.

### P6 — Mutable Journal Pagination Clarification
- Removed any assumption that priority-0 records always fit within the first 20 items.
- When `nextCursor` begins with `"0:"` (keyset priority bucket `0`), `FixtureOperations` displays an explicit warning: *"Additional active or recovery-required operations exist on later pages. Choose Load more to inspect them, or Refresh operations to reload from the top."*
- Documented limitation: keyset pagination over a live mutable journal without snapshots means newly created or mutated operations sorting ahead of an active cursor appear on the next `Refresh operations` (`cursor = undefined`), while client deduplication by `operationId` prevents duplicates if an item shifts onto a later page.
