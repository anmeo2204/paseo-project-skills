| **P1** | Typed update detection without inferring updates from unequal SHAs | `classifyCatalogUpdates()` distinguishes `no_stable_releases`, `unconfigured`, `up_to_date`, `update_available` (strictly newer SemVer), `newer_than_latest`, `moved_tag` (retargeted or deleted tag — never treated as a normal update), `custom_revision`, and `legacy_unpinned`, plus per-release `relation` (`active \| newer \| older \| same_commit \| uncompared`). |
| **P2** | Displayed revision consistency | `catalog.resolve` binds `latest_stable` (`expectedTag` / `expectedCommitSha`) and `specific_version` (required `expectedCommitSha`) to the displayed commit SHA; rejects with `stale_selection` if the remote tag moved between listing and resolution, preserving existing settings and refreshing releases. |
| **P3** | Async lifecycle safety | Monotonic attempt/draft-generation guards reject delayed `catalog.resolve` / `catalog.releases` responses across A → B → A edits, host switch, disconnect, unmount, and concurrent settings edits. Active catalog resolution/save lifts `catalogBusy` to `HostScreen` → `RecommendationRun` → `PreviewRun` / `FixtureApprovalPreview`, immediately clearing and disabling Preview/Approval submissions. |
| **P4** | First-use UX | On an unconfigured host (`catalogRef === ""`), **Scan & Recommend** resolves, validates, and pins `Latest Stable` using optimistic concurrency (`settings.revision`) before scanning. Never auto-replaces an existing pinned revision and never auto-Applies. |
