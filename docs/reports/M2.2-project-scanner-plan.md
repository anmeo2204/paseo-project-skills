## 2. Evidence collection

1. **Xác thực và đi từ root.** Dùng canonical directory do luồng Foundation trả về. Ưu tiên danh mục metadata root có giá trị cao, mở rộng các member đã khai báo, sau đó duyệt theo lớp trong ngân sách để tìm ứng dụng độc lập. Với Git root/worktree, ghi marker `.git` là file hoặc directory; không mở `.git`, không truy tìm common dir hay parent repo. Không cần Git executable. Với non-Git dùng cùng một pipeline.
2. **Workspace.** Đọc chọn lọc `package.json#workspaces` (array hoặc `packages`), `pnpm-workspace.yaml`, `go.work use`, `angular.json#projects`, và `lerna.json#packages` nếu có. Marker như `nx.json` và `turbo.json` chỉ ghi tooling. Resolve member paths tương đối dưới boundary, cho phép `.` làm root declaration; reject absolute, drive/UNC, backslash, escape, symlink và không expand pattern qua thư mục bị bỏ. Hỗ trợ pattern phổ biến với matcher giới hạn có semantics được fixture kiểm chứng, gồm exclusion của pnpm; pattern chưa hỗ trợ báo warning và tiếp tục discovery nông. Không thực thi config JS, đọc Go replacement path bên ngoài, hoặc tải workspace từ network.
3. **Nhiều ứng dụng.** Mỗi directory có manifest hợp lệ hoặc framework marker đủ mạnh có thể tạo boundary kể cả khi không phải workspace member. Lưu quan hệ giữa workspace root và member theo manifest, giữ cả nested application độc lập. Gắn filename/config/dependency evidence vào boundary gần nhất phù hợp. Dependency ở root workspace vẫn thuộc root; member chỉ tham chiếu shared declaration khi detector có quan hệ phù hợp, không copy mọi kết luận xuống member.
4. **Đọc chọn lọc.** Parse JSON/YAML được allowlist theo schema từng phần và scan dòng/khối `go.mod`/`go.work` bằng tokenizer giới hạn. Thu dependency names, section production/dev/peer/optional, version constraint an toàn và package-manager declaration. Với URL, local path hoặc VCS spec, giữ loại spec và bỏ giá trị gốc. Script chỉ góp tên chuẩn như build/test/lint hoặc dấu hiệu tool nếu có parser an toàn theo allowlist; không trả command text. Lockfiles, framework config executable, tài liệu và rule files chủ yếu là marker, không tải lockfile để suy transitive deps. Chỉ đọc prefix đã giới hạn khi format cần xác nhận, như WordPress header hoặc SKILL frontmatter.
5. **Phân loại.** `direct` ghi điều quan sát được như package được khai báo, workspace member được liệt kê hoặc header hợp lệ. `inferred` ghi suy luận từ rule có ID, kèm evidence refs, ví dụ Next.js App Router từ package và marker route phù hợp trong đúng boundary. `unknown` được dùng cho câu hỏi chưa đủ evidence như backend database đang chạy, hoặc khi coverage bị giới hạn. Evidence thiếu trong lượt scan không khẳng định công nghệ vắng mặt. Khi package manager khai báo mâu thuẫn lockfile, giữ cả hai evidence và warning; ưu tiên declaration cho ý định đã khai báo, chưa khẳng định manager đã chạy. Không có confidence score.

## 3. Scanner service và detector interface

- **Bounded traversal/reader.** Một scanner session tạo inventory theo breadth-first có ưu tiên metadata root và declared members, thứ tự bytewise trong mỗi lớp. Theo dõi budget chung, relative paths, file kinds và warnings. Reader policy áp dụng cả với file do detector yêu cầu. Đọc một lần cho cùng candidate trong session khi phù hợp; parser failures chỉ ảnh hưởng evidence phụ thuộc file đó.
- **Detector registry.** Danh sách tĩnh các module tin cậy có `id`, `candidates` (tên hoặc pattern metadata được phép), tùy chọn `discoverMembers` và `detect(context)`. Context cấp inventory chỉ đọc, boundary, đọc metadata giới hạn do core kiểm tra, signal và hàm emit facts/warnings. Detector không có đường dẫn tuyệt đối tùy ý, shell runner, Paseo provider API hoặc Catalog Loader. Thêm detector mới bằng module và một mục đăng ký, không đổi traversal, I/O, RPC hay lifecycle. Kiểm thử một detector giả mới để chứng minh extension point.
- **Hai pha.** Detector manifest góp workspace/boundary candidates trước. Sau đó chạy detection theo boundary đã chốt; hợp nhất fact theo boundary/kind/key/value, giữ origins và sắp xếp output. Dùng Node built-ins, Zod và YAML dependency hiện có. Không có database, cache qua scan, dynamic plugin discovery hoặc engine chấm điểm.

## 4. Project evidence schema đề xuất

| Thành phần | Trường chính |
| --- | --- |
| `ProjectEvidence` | `schemaVersion: 1`, `target`, `boundaries[]`, `facts[]`, `evidence[]`, `inventory[]`, `warnings[]`, `coverage`. |
| `target` | `canonicalDirectory` được revalidate trên daemon, `marker: git_directory \| git_file \| unknown`. Host identity lấy từ transport ở client envelope; root device/inode dùng nội bộ để so sánh trong scan. |
| `boundary` | `rootRelativePath` (root dùng `.`), `kind: root \| application \| package \| workspace` dưới dạng roles có thể đồng thời, quan hệ `workspaceRoot?` hoặc membership edges, `evidenceIds[]`. |
| `fact` | `boundaryPath`, `kind` (language/framework/manifest/package_manager/dependency/build/test/database/queue/router), `key`, value có cấu trúc giới hạn, `basis: direct \| inferred`, `evidenceIds[]`, `ruleId?` bắt buộc khi inferred. Dependency có ecosystem, name, scope và optional version constraint đã lọc. |
| `evidence` | ID xác định từ relative path + selector/type ổn định, `relativePath`, `kind: presence \| declaration \| header`, `selector?` là key chuẩn như `dependencies.react` hoặc field ID; không có excerpt. |
| `inventory` | Relative path, scope boundary, kind, layout/source, declared ID nếu hợp lệ, metadata state, customization evidence refs. |
| `coverage` | `status: complete \| partial` theo policy v1, các giới hạn đã chạm và câu hỏi `unknown` kèm lý do theo boundary. `warnings[]` dùng code, relative path an toàn khi phù hợp và detector ID tùy chọn. |

Cùng input và cây ổn định trong budget cho output cùng thứ tự và nội dung. Request IDs ở envelope; không đưa timestamp hoặc duration vào evidence. Trên cây đang chỉnh sửa, giữ kết quả partial khi mục con biến động được phát hiện. Root đổi identity trả lỗi và bỏ toàn bộ evidence. Partial do timeout có thể khác nhau theo tốc độ I/O, vì vậy không dùng làm bằng chứng phủ định. Evidence v1 không có recommended IDs, raw project content hay provider activation.

## 6. Security, performance và semantics khi có lỗi

- Dùng lại validation Foundation, yêu cầu path scan đã canonical và xác nhận lại ngay trước khi mở root; root khác canonical hoặc identity đổi trong lượt thì fail. Kiểm tra containment bằng relative path theo hệ điều hành; không đi lên parent, follow symlink/junction, đọc mount con khác device, hard-linked regular file hoặc special file. Kiểm tra root và từng ancestor, mở regular file read-only với no-follow khi OS hỗ trợ, đối chiếu identity/size bằng fstat trước khi đọc; đọc bounded chunks và kiểm tra lại sau khi đọc. Reject path NUL, traversal, absolute target-relative candidate và path không hợp lệ.
- **Ranh giới triển khai.** Node pathname APIs và no-follow trên segment cuối không loại bỏ hoàn toàn race thay ancestor trong cây bị sửa đồng thời bởi tiến trình đối nghịch. Đề xuất v1 cho target local do user quản lý, fail/skip khi phát hiện thay đổi, test symlink ổn định và race có thể kiểm soát. Nếu cần invariant chống tiến trình đối nghịch thay ancestor, cần primitive descriptor-relative có no-follow từng segment hoặc sandbox đọc phù hợp trước khi cam kết mức bảo đảm đó. Đây là quyết định scope trước triển khai.
- Reader chỉ mở chính xác các metadata candidates được khai báo. Prune `.git`, `node_modules`, `vendor`, build/dist/output/coverage, caches và hidden paths ngoài allowlist. Chặn `.env*`, private key/certificate credential candidates, package-manager auth/config như `.npmrc`, Composer auth, SSH artifacts, và `wp-config.php` kể cả khi detector yêu cầu. Không đọc arbitrary code, toàn bộ docs/rules, secret values hoặc runtime connection. Metadata có thể chứa trường nhạy cảm bất ngờ; chỉ trích field allowlist, không gửi raw manifest, arbitrary URLs, lệnh hoặc exception text. Không network, telemetry nội dung, install, shell, agent hoặc ghi target.
- **Giới hạn đề xuất để đo bằng fixture.** Depth 6 cho discovery thường, tối đa 10 cho declared members; 256 directories, 8.000 entries quan sát, 64 boundaries, 256 file reads, 128 KiB/file, 8 KiB cho prefix, 4 MiB tổng bytes, 8 giây deadline hợp tác, 256 KiB kết quả, tối đa 64 warnings và hai lượt scan đồng thời mỗi installation. Count cả entries bị skip và limit per-directory trước khi sort. Directory quá lớn bỏ cả listing chưa hoàn chỉnh và báo partial để thứ tự filesystem không quyết định tập kết quả. Deadline kiểm tra giữa thao tác và các chunk, đóng handles bằng finally; thao tác OS đã vào kernel có thể kết thúc sau deadline.
- Malformed/inaccessible metadata hoặc budget exhaustion trả `partial` và evidence đã xác nhận. Lỗi root, cancel và target identity mismatch không trả snapshot. Code ổn định như `malformed_manifest`, `permission_denied`, `unsafe_entry`, `unsupported_workspace_pattern`, `max_depth`, `byte_budget`, `deadline`. Coverage `complete` chỉ có nghĩa đạt policy của scanner, kể cả khi công nghệ là unknown.

## 7. Typed RPC, isolation và tích hợp M2.4

Đề xuất `defineSubscription` tên `target.scan`, một terminal result mỗi lần gọi, không streaming raw evidence. SDK 0.17.4 có `server.handle`, `ctx.signal`, `ctx.push`, client `useSubscription`. Unary handler hiện chỉ có `paseo`; subscription cho phép đóng request khi release hoặc disconnect mà không cần cancel RPC riêng.

- **Input Zod strict** — `{ requestId, canonicalDirectory }`, giới hạn cả hai. Client chỉ gửi từ `target.validate-directory` ready của active host/selection. Server vẫn chạy lại validation và lấy root identity, không nhận host ID tùy ý, manifest paths, detector options, catalog ref hoặc cwd thứ hai. Đây là RPC cho plugin client được tin cậy, không biến canonical path thành chứng nhận quyền truy cập của client không tin cậy.
- **Event** — `{ requestId, status: "ready" | "partial", evidence }` hoặc `{ requestId, status: "error", code }`. Root error dùng code Foundation và thêm `target_changed`, `busy`, `scan_failed`. Cancel/disconnect kết thúc subscription qua transport, drop event nếu signal đã abort; deadline do scanner trả partial khi còn kết nối. Verify khả năng terminal event được nhận đúng trên SDK 0.17.4 trước khi nối UI.
- **Isolation.** Nối subscription theo bộ `hostId + screen instance + selection generation + canonicalDirectory + requestId`, dựa trên key/remount đã có ở Foundation. Release trên target switch/offline/unmount/rescan. Bỏ response đến muộn kể cả A → B → A cùng path. Server không giữ result dùng lại liên host hoặc target. Plugin cleanup abort session đang chạy, đóng handles và giải phóng slot. Kiểm tra client+transport tại M2.2 bằng SDK harness; UI đầy đủ thuộc M2.5.
- **M2.4.** Recommendation Engine nhận evidence v1, catalog snapshot và capability nếu cần như input độc lập. Kết hợp theo active host/target/request, dùng evidence refs để lý giải. Evidence partial/unknown giữ đúng semantics. Scanner chạy được khi catalog chưa cấu hình hoặc provider unavailable.

## 9. Test plan và acceptance

- **Coverage theo nhóm.** Fixtures độc lập Common, Go (HTTP, queue, DB), React, Next App/Pages/both, Angular nhiều project, Laravel HTTP/queue/migrations, WordPress standalone plugin, classic/block theme và site. Kiểm tra tín hiệu dương và âm, ví dụ chỉ có folder `app`, `routes` hoặc `wp-content` không đủ để gán framework. Metadata có dependency DB chỉ tạo declaration evidence.
- **Mixed projects.** Monorepo có package workspaces, exclusions, shared root dependencies và app độc lập; Go workspaces có sibling modules; project mixed Go/PHP/JS. Kiểm tra đúng paths, membership, scope và output ổn định khi tạo files theo thứ tự khác. Fixture công nghệ không hỗ trợ vẫn có manifest marker hoặc unknown. Fixture detector giả mới đi qua core chưa sửa.
- **Target và inventory.** Git root, Git worktree có gitfile trỏ ra ngoài, non-Git, canonical paths, hai host dùng cùng path, root replacement. Canonical/provider skill trùng ID, malformed skill, nested `AGENTS.md`, rules và provenance. Kiểm chứng inventory không gán bừa customization hay activation.
- **Boundary và lỗi.** Sentinel secret trong `.env`, private key, `.npmrc`, `wp-config.php`, ignored/dependency directories, URL credential trong manifest, FIFO/symlink/hardlink, escaped member path, đổi ancestor/file giữa kiểm tra, malformed JSON/YAML/Go và permission thực khi chạy non-root. Đo các candidate được mở, xác nhận file cấm chưa được mở; assert RPC không chứa sentinel. Fixture script sẽ ghi sentinel nếu bị chạy, kiểm tra sentinel không xuất hiện. So sánh file hashes, Git HEAD/status và tree trước/sau, dùng file reads tới fixture ngoài boundary làm negative control.
- **Budget và lifecycle.** Hit depth/count/size/total/RPC/deadline, oversize directory, cancel giữa scan, cleanup/reload và slot phục hồi, host/target switch, reconnect/unmount và stale response A → B → A. Dùng clock/reader seam cho test deadline, thêm smoke run với FS thật. Zod chặn input thừa và payload có field ngoài schema xuất qua RPC.
- **Tiêu chí hoàn thành M2.2.** Typecheck và toàn bộ 26 regression tests tiếp tục PASS cùng scanner suite mới. Paseo 0.17.4 smoke test subscription với nhiều fixture temp độc lập, không cần catalog/AI, xác minh cancel và event cuối, manifest evidence đúng và target giữ nguyên. Catalog 19 skill là checklist coverage cho evidence, không phải số skill scanner phải phát ra.

## 10. Blocker và quyết định chờ review

1. **Boundary assurance.** Duyệt v1 trên local target do user quản lý với Node built-ins, kiểm tra race và hạn chế đã nêu. Nếu cần chống đối thủ đổi ancestor đồng thời, chọn phương án descriptor-relative hoặc sandbox trước khi triển khai; đây là blocker với yêu cầu bảo đảm mức đó.
2. **RPC và limits.** Duyệt one-result subscription có cancellation, budget khởi điểm và partial semantics. SDK 0.17.4 có contract cancellation; behavior runtime của terminal event cần smoke test khi triển khai.
3. **Coverage và privacy.** Duyệt danh mục detector theo 7 nhóm đủ 19 skill, inventory provider theo path project và chỉ đọc metadata allowlist. Runtime DB/queue, file ngoài boundary, ngữ cảnh task, provider activation và mức customization chưa có baseline được giữ unknown hoặc ngoài phạm vi quan sát.
