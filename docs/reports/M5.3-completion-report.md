## 1. Summary of Implemented Scope (D1–D4 & P1–P4)

| Item | Requirement | Implementation & Verification |
| --- | --- | --- |
| **D1** | Group by `Applicability` (default), `Boundary`, and `Observed Status` | Implemented pure metadata-driven `filterAndGroupSkills()` in `client/skill-selection.ts` and compact group-by pills in `client/recommendation-results.tsx`. | **D2** | Explicit observed-file labels & non-activation disclaimer | Renamed observed labels to `Observed in project`, `Multiple copies observed`, `Not observed`, and `File state unverified`. Displayed an explicit non-activation disclaimer whenever any skill has `inventory.state !== "not_observed"`. |
| **D3** | Auto-reveal matching `Unknown` skills during search/filtering | Under `By Applicability`, `Unknown` remains collapsed by default (`showUnknown = false`), automatically reveals matching items during active search or relevant filtering (`Unknown`, `Selected`, or any observed-file filter), and restores the user's saved collapse state when cleared. |
| **D4** | M5.2 mid-refetch & delayed target-A provider snapshot regression tests | Added targeted regression test in `tests/project-provider-ux.test.mjs` verifying that delayed Target A provider snapshots cannot leak into Target B and that `Select Detected Providers` stays disabled (`Detecting providers…`) during mid-refetch (`Retry discovery`). |
| **P1** | Bulk selection scope across complete scan result | `Select Recommended (+N)` adds all `recommended` skills from the complete scan result (even while search/filters hide them), displays the exact additional count `(+N)`, preserves manual selections, and never selects `optional` or `unknown`. `Clear Selection` clears all selected skills while preserving target providers. |
| **P2** | Hidden selection visibility & provider names in summary | Counts selected skills hidden by search, filters, **and** collapsed groups (`hiddenSelected`). `Show Selected` resets conflicting filters and reveals all selected skills (including selected `Unknown` skills). Selection Summary displays actual target provider names (`Codex, Kiro`) or `none (canonical .agents/skills only)`. |
| **P3** | Selection invalidation & no-op guard | Search, filter, group-by, and disclosure state live inside `RecommendationResults` and never mutate `selected` or invalidate Preview. `RecommendationRun.select()` tracks `selectedRef` and skips advancing `selectionGeneration` on true no-op actions while preserving batched A → B → A invalidation on real mutations. |
| **P4** | Catalog scalability (`19`, `100`, `512` skills) | Benchmarked synthetic catalogs of `19`, `100`, and `512` skills on Desktop and compact Mobile layouts without premature virtualization (see Section 5). |

## 5. Scalability Findings (P4)

Measured via `tests/skill-selection-ui.test.mjs` across synthetic catalogs of `19`, `100`, and `512` skills (Node 22 + React Test Renderer):

| Catalog Size | Layout | `filterAndGroupSkills` (2 passes: full + filtered/boundary) | Full React Render (`RecommendationResults`) |
| --- | --- | --- | --- |
| **19 skills** | Desktop (`compact: false`) | `0.08 ms` | `3.84 ms` |
| **19 skills** | Mobile (`compact: true`) | `0.08 ms` | `3.82 ms` |
| **100 skills** | Desktop (`compact: false`) | `0.23 ms` | `17.74 ms` |
| **100 skills** | Mobile (`compact: true`) | `0.23 ms` | `22.09 ms` |
| **512 skills** *(max catalog limit)* | Desktop (`compact: false`) | `0.89 ms` | `89.63 ms` |
| **512 skills** *(max catalog limit)* | Mobile (`compact: true`) | `0.89 ms` | `14.24 ms` |

**Finding:** Even at the hard catalog ceiling (`512` skills), filtering/grouping stays `<1 ms` and full initial render stays `<90 ms` on Desktop and `<25 ms` on compact Mobile (with `Unknown` collapsed by default). **No virtualization or architectural changes are needed.**
