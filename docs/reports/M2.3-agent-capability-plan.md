## 4. Execution strategy và isolation

1. **Evidence-only.** M2.4 truyền phiên bản scan evidence đã chiếu gọn (boundary, facts, coverage, existing skill inventory cần thiết và evidence references), catalog SHA và danh sách ID/name/description. Loại canonical absolute path, per-user identifiers không cần thiết, raw manifest/source/rules, file descriptors không dùng, supporting bytes, URL chứa credential và secret values. Dùng reference ID thay cho relative path hoặc dependency name nhạy cảm nếu không cần gửi. Giữ mapping để giải thích kết quả ở plugin. Scheme allowlist và limits áp dụng trước khi tạo agent.
2. **Input là dữ liệu không tin cậy.** Serialize JSON riêng khỏi trusted instruction và output schema do plugin/M2.4 sở hữu. Catalog description, path, dependency name và inventory có thể chứa prompt injection hoặc dữ liệu riêng tư. Không đưa chúng vào system prompt hoặc sử dụng làm command/tool parameters. Kiểm tra provenance của input cùng host/request trước khi chiếu. Zod và output validation giới hạn kết quả, nhưng delimiter và prompt không enforce tool permissions. Người dùng cần duyệt việc gửi metadata đã chiếu đến provider và chấp nhận retention theo Paseo/provider.
3. **Placement.** Daemon tạo `mkdtemp` private, canonicalize, kiểm tra nằm ngoài target, home project và catalog checkout. Không copy file project, không truyền target cwd, worktree, parent, attachments hoặc credentials. Dùng dedicated directory workspace với title cố định; ưu tiên tạo workspace không prompt, tránh nhánh auto-naming của daemon cho implicit workspace mới có initial prompt. Khi runtime smoke test, xác minh workspace placement, không có AI title call ngoài dự kiến, và không có native config thay đổi ngoài history được duyệt.
4. **Enforcement.** Empty cwd giảm dữ liệu tự nạp tại workspace; native agent vẫn chạy theo quyền của daemon/provider. SDK source còn cho thấy daemon có thể inject internal Paseo MCP/native tools, plugin hooks có thể append prompts hoặc bổ sung MCP và có hook xử lý permission. `mcpServers: {}` và không set `toolPolicy` không chứng minh mọi tool đã tắt. Không tự đổi cấu hình máy, SLP hoặc provider. Dùng mode per-session có thể xác minh, không preapprove, không gửi allow response. Permission bất ngờ dừng và archive. Nếu external hook hoặc auto mode có thể cấp quyền trước plugin, block từ preflight. [Launch config và tool injection](https://github.com/getpaseo/paseo/blob/v0.17.4/packages/server/src/server/agent/agent-manager.ts) · [Plugin lifecycle](https://github.com/getpaseo/paseo/blob/v0.17.4/packages/plugin/src/server/lifecycle.ts)
5. **Production gate.** Cần profile đã kiểm chứng theo host, daemon/provider version và mode thực tế, có ranh giới ngăn đọc/ghi target và ngăn chạy project commands, browser/MCP hoặc network tools ngoài policy. Kết nối đến model service là network của integration, tách khỏi network tools của agent. Nếu SDK controls không đủ, chỉ đánh giá tiếp trên daemon/profile cô lập do user chuẩn bị và duyệt, không cấp quyền bổ sung cho host hiện tại. Synthetic pass xác nhận execution path, không mở production gate.

## 5. Structured output

- **Ưu tiên native.** Với Codex đã đủ điều kiện, đặt trusted JSON Schema vào initial `create.outputSchema`, await `waitForFinish`. Với ACP hoặc model chỉ có text, dùng fresh session rồi `run` hoặc initial prompt yêu cầu đúng một JSON document. Cả hai chỉ nhận `idle` với non-empty `lastMessage` của turn đúng. Nếu cần debug khác biệt, fetch bounded timeline theo turn/request; không trộn commentary, reasoning, tool output hay text của turn cũ. Không nhận response khi turn final không khớp agent/request đang xử lý.
- **Validate.** Giới hạn output plugin nhận để parse ở 16 KiB UTF-8. SDK `lastMessage` có thể đã materialize upstream hơn giới hạn; không gọi đây là hard provider token cap hoặc transport cap. JSON parse toàn bộ text sau trim; v1 có thể chấp nhận một fenced JSON block duy nhất với text ngoài fence rỗng. Zod strict và bounded arrays/strings. Không salvage từng đoạn JSON từ prose. M2.4 sở hữu semantic validation cho IDs/evidence refs đã cung cấp và recommendation rules.
- **Retry.** Mặc định một turn, tối đa một retry malformed output nếu policy được duyệt, dùng fresh same provider/model và cùng guard. Chỉ gửi lỗi schema dạng code, không quote malformed text. Native retry giữ initial schema. Không retry tự động khi permission, timeout, auth, transport uncertain, mismatch, unsupported hoặc cleanup chưa xác nhận. Giới hạn tổng ngân sách gồm retry, đề xuất discovery 15 giây, create 20 giây, turn 45 giây và cleanup grace 15 giây. Các số này là deadline của plugin, không chứng minh native process dừng khi hết giờ.

## 6. Architecture và contract

| Thành phần | Thiết kế đề xuất |
| --- | --- |
| Capability descriptors | Một registry nhỏ cho bốn provider, ghi route, model selection caveats, structured output mode, restrictions đã xác minh và scope/version verification. Kết hợp Foundation selection trên active host với preflight tại temp cwd. Availability và policy eligibility là hai trường riêng. Không chạy discovery/AI tự động khi chỉ tick provider. |
| Executor chung | `executeStructured<T>(input, outputContract, { signal, paseo })` là interface server nội bộ. Input gồm request ID, provider/model đã chọn, purpose cố định và payload đã project. Output contract là trusted Zod schema và optional native JSON Schema cho cùng shape. Capability layer chỉ chạy/validate technical output; không sinh Skill IDs hoặc rules. Provider-specific code chỉ cấu hình mode/options và native/text routing. |
| Kết quả | `ok` trả request ID, effective provider/model, parsed value và optional usage đã lọc; `error` trả mã như `provider_unavailable`, `model_unavailable`, `model_mismatch`, `capability_unverified`, `unsafe_execution_profile`, `input_limit`, `permission_required`, `invalid_output`, `output_limit`, `timeout`, `cancelled`, `provider_error`, `cleanup_failed`. Không trả raw exception hoặc prompt transcript. |
| Typed boundary | Giữ executor nội bộ trước; không mở RPC gọi arbitrary prompt, cwd, provider options hoặc schema. Nếu M2.3 cần hiển thị trạng thái, thêm read-only capability contract theo host; production execution RPC thuộc M2.4 và nhận input đã định kiểu. Dùng SDK harness cho capability smoke; không giữ test RPC. |

Lifecycle đề xuất: gắn UUID/ownership labels không chứa dữ liệu dự án; giữ agent ID dự kiến trước create, workspace ID ngay khi nhận. Với text route có thể dùng create idle rồi `run` sau verify snapshot/model, dùng idempotency khi phù hợp. Với native initial prompt, dùng explicit unique agent ID và preflight trước khi gửi vì prompt bắt đầu cùng create. Không retry create khi acknowledgment không rõ. Khi cancel/timeout, reconcile bằng exact ID và ownership marker, xử lý create resolve muộn rồi archive. Release listeners; archive agent và workspace đã xác nhận thuộc request trước khi xoá temp dir. Không archive resource người dùng. Nếu chưa xác nhận close, trả cleanup error, giữ temp để tránh xóa khi process còn hoạt động, và ghi receipt tối thiểu không chứa nội dung để đối soát. Chưa cam kết tự recovery sau hard kill; kiểm tra guard này bằng fixture. Background archive không xóa lịch sử Paseo/native provider và không đảm bảo dừng billing của request đã gửi.

## 7. Fallback policy

- Provider offline, model không có hoặc lỗi auth/binary là **unavailable**. Có thể báo lý do và cho người dùng tự chọn lại cùng host.
- Provider tạo được session nhưng effective controls thiếu, chưa chứng minh hoặc có conflict với hook là **blocked for this execution profile**. Không mở production agent để thử trên evidence thật.
- Giữ khả năng xem scan evidence và catalog độc lập. M2.4 có thể đề xuất chế độ deterministic/manual riêng sau khi duyệt. Không tự chuyển provider/model, dùng default ngầm, hạ cấu hình bảo vệ hoặc bỏ schema khi native path thất bại. JSON text là route được chọn trước cho provider đủ điều kiện, không phải retry bằng profile yếu hơn.

## 8. Files dự kiến khi được phê duyệt

- `tests/agent-capability.test.mjs` cho mock SDK, synthetic fixture và regression. `README.md` cho scope và luồng xác minh. Dùng Node built-ins, Zod và SDK hiện có.

## 9. Verification và token/credit budget

**Automated, 0 model calls.** Mock SDK cho discovery loading/unavailable/error, model IDs chứa slash, runtime model fallback bị phát hiện, Cursor config caveat, Antigravity default guard, Kiro hook/profile block, input redaction và prompt injection strings, native-schema forwarding và JSON text routing. Test lastMessage null/malformed/oversize, schema type lỗi và retry cap, permission không được allow, timeout/cancel/disconnect, host/target stale responses, close fail và create ACK đến muộn. Kiểm tra temp path quyền riêng, không truyền target cwd và cleanup chỉ resource đã sở hữu. Chạy typecheck và 44 regression tests.

**Runtime, chỉ sau review và authorization riêng.** Kiểm tra daemon/CLI version và profile trước. Dùng empty temp workspace và payload synthetic vài trường để trả một object nhỏ có nonce. Mỗi provider đủ preflight dùng **một model turn**: Codex thử native schema, Cursor/Kiro/Antigravity thử JSON text. Đối chiếu output, effective mode/model và history/cleanup; skip kèm lý do nếu thiếu auth/models, có hook approve, hoặc không có profile đã duyệt. Một cancellation probe bổ sung tối đa trên provider ưu tiên, archive lúc turn đang chạy và kiểm tra không còn process/tool work liên quan. Có thể xác minh cancel phần còn lại bằng fixture đến khi người dùng duyệt thêm. Kiểm tra deny-read/deny-write và egress trên host cô lập bằng sentinel synthetic và kiểm tra ranh giới ngoài model khi khả thi; nếu cần agent turn riêng để kiểm tra policy, xin duyệt thêm, không gộp vào lượt thử output rồi suy từ việc agent không gọi tool. ## 10. Blockers và quyết định cần phê duyệt

1. **Scope M2.3.** Duyệt capability layer chạy fixture/mocks, mặc định chặn evidence thật. Nếu production AI là điều kiện GO M2.4, cần host/profile có isolation enforcement và runtime evidence. Codex read-only và temporary cwd chưa đủ để cam kết chặn đọc target hoặc mọi tool.
2. **Host approval policy.** Duyệt kiểm tra host hooks/profile theo read-only preflight. Nếu SLP auto-approval Kiro hoặc daemon/plugin tools vẫn có thể cấp quyền, skip provider trên host đó; không sửa SLP hoặc host config. Duyệt dùng host cô lập riêng nếu muốn kiểm chứng thêm.
3. **Data và retention.** Duyệt metadata projection gửi provider, lựa chọn model tường minh, và việc Paseo/native history có thể lưu prompt/output dù đã archive. Nếu cần không lưu history, API public hiện tại không cung cấp guarantee đủ cho chiến lược này.
4. **Budget.** Duyệt tối đa bốn lượt probe synthetic và một lượt cancel tùy chọn, cùng deadline, output cap và retry policy cho runtime tương lai. Nếu Cursor model switching có thể lưu preferences, giới hạn ở model hiện hành cho probe.
5. **Tiêu chí GO.** MVP có executor chung, fail-closed guard và tests qua. Capability chỉ chuyển sang production-eligible theo host/provider/model/mode đã verification; nếu không có profile đạt, M2.4 giữ evidence review hoặc fallback đã duyệt và báo AI unavailable/blocked đúng lý do.
