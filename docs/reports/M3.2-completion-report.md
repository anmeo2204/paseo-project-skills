## 3. Planning và diff semantics

Mỗi selected skill lập kế hoạch cho **entrypoint và toàn bộ supporting files** tại `.agents/skills/<id>/` dưới chính canonical target đã chọn, kể cả khi target là nested directory. Không chuyển sang Git root hoặc provider layout. Legacy catalog không cần applicability metadata; `applicability.json` nếu có được xử lý như file package bình thường. Không lập kế hoạch xóa file ngoài snapshot.

Output được sort bytewise theo relative destination, intent IDs cũng được sort. Mỗi file có proposed size/SHA-256/POSIX mode và một trạng thái:

- `create`: destination chưa tồn tại và các ancestors đã quan sát hợp lệ.
- `unchanged`: bytes/hash và toàn bộ permission bits khớp; planned mode là `0644` hoặc `0755` từ Git mode.
- `conflict`: file thường hiện có khác bytes hoặc mode; không cấp quyền overwrite.
- `blocked`: entry không an toàn, sai loại, không đọc được, đổi trong lượt Preview hoặc vượt read/diff budget.

Text UTF-8 hợp lệ, không chứa binary control characters, có unified diff với một contiguous hunk và tối đa ba context lines ở mỗi đầu; giữ CRLF và dấu thiếu newline cuối file. Mode-only changes dùng mode headers. Binary changes có before/after size/hash/mode, không gửi raw binary bytes. Unchanged files không cần diff. Path traversal, reserved names, file/directory collisions và case/Unicode-normalization aliases trong package bị từ chối trước destination reads.

## 4. Filesystem guards, lifecycle và limits

Scanner và planner dùng chung root identity, descendant path, device/inode, permission/link count và file-version guards. Scanner giữ nguyên metadata allowlist. Preview dùng reader riêng để đọc đầy đủ destination package, với lstat từng segment, realpath consistency, no-follow/nonblocking open khi có, và lstat/fstat trước/sau đọc. Symlink, hardlink, special file, child mount và wrong-type paths bị chặn. Các destination/ancestors đã quan sát được kiểm tra lại sau final settings read; thay đổi làm entries liên quan thành `blocked` hoặc trả `target_changed` nếu root bị thay.

Giới hạn v1: **2.048 files**, **1.024 bytes/32 segments mỗi destination**, **1 MiB mỗi existing file**, **8 MiB tổng destination reads**, **32.768 lstat checks**, **128 KiB mỗi text diff**, **1 MiB toàn response JSON**. Read/diff quá lớn trả blocked entry; file-count/check/deadline/response-budget lỗi trả `limit_exceeded`, không publish plan bị cắt ngắn. Filesystem phase có cooperative deadline **8 giây**; catalog giữ deadline riêng **20 giây**. Một Preview chạy mỗi installation. Dispose abort và đợi active work settle.

## 7. Known limitations và bàn giao

Preview là quan sát local-first, không phải atomic filesystem snapshot hoặc adversarial filesystem sandbox. Không thể đối chiếu same-path root replacement xảy ra trước request với inode của scan cũ; thay vào đó Preview revalidate và đọc current destinations. Filesystem có thể thay đổi sau kiểm tra cuối, cooperative deadline không ngắt syscall đang chạy. Safe Apply phải revalidate độc lập và cần quyền ghi riêng. Single-hunk diff ưu tiên bound thời gian/bộ nhớ, không bảo đảm minimal diff. Windows/Linux và Preview UI chưa được runtime-test trong milestone này.
