## Writer và kết quả race

[Native helper](native/anchored-writer.m) pin directory handles từ anchor tới parent, dùng `O_DIRECTORY | O_NOFOLLOW`, đối chiếu metadata trên handle với entry parent-relative, và recheck linkage quanh mutation. Target descendants phải cùng device, thuộc user hiện tại và qua kiểm tra mode/flags/ACL. Preflight kiểm observations, path/collision, source hash, giới hạn và trạng thái toàn plan. Directory effects theo thứ tự cha trước con, tạo bằng `mkdirat` mode `0755` với umask riêng của helper. Leaf mở bằng `openat(O_RDWR | O_CREAT | O_EXCL | O_NOFOLLOW)` mode `0600`, write qua handle vừa tạo, áp mode đã duyệt, sync, đọc lại hash, close, sync parent và kiểm lại identity của tên. Existing files chỉ mở đọc. Writer không dùng Node full-path fallback và không unlink/rmdir final paths.

Ledger ghi `created_verified`, `created_incomplete`, `not_attempted`, `unchanged_verified`, `observation_changed` hoặc `ownership_unknown` theo evidence. Kết quả tổng thể phân biệt `completed`, `failed_before_write`, `partial_failure` và `uncertain`. `fsync_completed` ghi nhận các syscall đã hoàn tất trong lượt thành công. File mới có thể hiện ra trước khi đủ bytes, và nhiều file có thể dừng giữa chừng.

- Barrier sau linkage check, ngay trước exclusive create. Regular leaf khác bytes, regular leaf cùng bytes, symlink và hardlink xuất hiện muộn đều bị từ chối. Fingerprint foreign giữ SHA-256, mode, dev/ino và symlink target khi áp dụng. Hai helper không dùng chung lock cùng tranh một leaf cho đúng một winner. Inode, bytes và mode kết quả khớp winner.
- Root hoặc ancestor bị replace ở barrier trước linkage check thì writer dừng trước create. Khi directory đã pin bị move sau lần check cuối, `openat` tạo file rỗng mode `0600` trong directory cũ, linkage check kế tiếp dừng lại với `partial_failure` và `created_incomplete`. Foreign leaf ở root/ancestor thay thế giữ nguyên fingerprint. Đây là giới hạn của handle pinning trước concurrent rename.
- `mkdirat` gặp foreign directory đã xuất hiện trả collision. Directory bị swap giữa lần lấy identity và lần mở handle trả `uncertain`, foreign mode/inode giữ nguyên. `mkdirat` không trả handle, nên khoảng giữa syscall và lần lấy identity đầu tiên vẫn cần giả định cooperative namespace.
- Fault seam tạo short positive writes thật và kiểm exact bytes/mode, kể cả binary, empty và executable. Inject `ENOSPC` tại byte **8.195** giữ file xong trước đó, file dở mode `0600` và các file sau ở `not_attempted`. Các ca zero write, chmod, sync, directory sync, readback và close trả partial. Fault close được báo qua seam sau khi thực hiện close thật.
- Kiro fixture Git dùng đúng retained bytes và mode, Git metadata giữ nguyên. Thay canonical dependency trước derived create thì derived leaf vẫn absent. Khi helper bị `SIGKILL` sau exclusive create, wrapper trả `uncertain`, giữ evidence đã nhận về file hoàn tất và đánh dấu leaf đang xử lý là `ownership_unknown`. Lượt chạy sau lấy được lock và dừng trước mutation do quan sát cũ đã stale.

Chi tiết từng outcome và fingerprint nằm trong [runtime acceptance](docs/evidence/m4.3/runtime-acceptance.json).

## Giao diện bàn giao M4.4

1. [Contract](server/native-writer-contract.ts) nhận snapshot observations, directory effects và bytes/mode/hash đã duyệt. `fixtureWriterRequest` đối chiếu manifest digest và xếp canonical trước derived, supporting files trước `SKILL.md` trong mỗi skill. Đây là bridge fixture. M4.4 sở hữu admission từ receipt, kiểm settings/ref/host và eligibility, provider/Git proof, receipt claim và journal.
2. Helper giữ descriptor của stable `writer.lock` mode `0600` ngoài target, trong coordinator directory riêng. `flock(LOCK_EX | LOCK_NB)` được lấy trước native preflight và trả `busy` nếu đã có holder. Giữ nguyên lock inode qua các lượt và không unlink lock. Scope thử nghiệm là hai plugin processes cùng daemon dùng cùng fixture coordinator directory. M4.4 cần gắn namespace ổn định vào daemon home đã được kiểm chứng ở M4.2, và giữ exclusion từ admission/claim tới journal settle.
3. Sau target I/O và close targets, helper còn giữ lock và gửi `ready_to_finalize` kèm provisional result. Parent hook `onFinalize` hoàn tất rồi wrapper gửi `FINALIZE`. Helper kiểm lại coordinator linkage, release lock, gửi terminal `result` và thoát. Test xác nhận contender vẫn `busy` trong hook. `mutation_intent` là telemetry trước syscall, có thể không tới parent khi crash. Nó chưa phải durable write-ahead barrier. M4.4 cần bước admission/ACK có journal bền vững trước mutation đầu tiên nếu dùng giao thức này.
4. Helper chết thì OS giải phóng lock khi descriptor đóng. Khi parent chết, helper phát hiện trong checkpoint hoặc qua pipe và thoát. Các ca kill ở barrier đã xác nhận contender lấy lại cùng lock inode. Checkpoint là cooperative và không ngắt syscall đang bị block. Crash sau release hoặc trước khi parent nhận terminal result vẫn cần reconciliation từ journal và filesystem. Không dùng lỗi transport để suy ra zero writes.
