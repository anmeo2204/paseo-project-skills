# M2.4A — Applicability Metadata Contract v1

**Trạng thái — Chờ review.** Thay phần schema, ví dụ và Common Skills trong [kế hoạch M2.4](M2.4-recommendation-engine-plan.md). Các semantics khác của kế hoạch tiếp tục áp dụng. Contract mô tả file cần tạo sau khi migration Project-Skills được phê duyệt riêng.

**Baseline đối chiếu.** Project-Skills tại `7f36043f2c18d4bf4c245a5a474c898244c83590` có 19 skill và chưa có file applicability. Evidence v1 và detector output được đối chiếu với plugin tại `9848519d025c288b854ac258e9c3de0f693c9f1e`.

## 1. Vị trí và schema chính xác

Mỗi skill có tối đa một file `skills/<slug>/applicability.json` cạnh `SKILL.md`. Dùng đúng tên file và chữ thường. Skill ID lấy từ thư mục trong CatalogSnapshot của cùng commit. File không khai báo ID, provider hay đường dẫn tới file khác.

Schema bên dưới là JSON Schema Draft 2020-12. Quy tắc encoding, duplicate keys, kích thước và provenance ở mục 4 cũng là bắt buộc. Khối schema dùng để validate các file bên dưới. Chỉ chép các mẫu ở mục 5 vào thư mục skill. [JSON Schema Draft 2020-12](https://json-schema.org/draft/2020-12/json-schema-validation)

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "Project-Skills applicability v1",
  "oneOf": [
    {
      "type": "object",
      "additionalProperties": false,
      "required": ["schemaVersion", "scope", "level"],
      "properties": {
        "schemaVersion": { "type": "integer", "const": 1 },
        "scope": { "const": "project" },
        "level": { "enum": ["recommended", "optional"] }
      }
    },
    {
      "type": "object",
      "additionalProperties": false,
      "required": ["schemaVersion", "scope", "appliesWhen"],
      "properties": {
        "schemaVersion": { "type": "integer", "const": 1 },
        "scope": { "const": "boundary" },
        "appliesWhen": { "$ref": "#/$defs/condition" },
        "recommendWhen": {
          "oneOf": [{ "const": "on_match" }, { "$ref": "#/$defs/condition" }]
        }
      }
    }
  ],
  "$defs": {
    "condition": {
      "type": "array",
      "minItems": 1,
      "maxItems": 4,
      "items": {
        "type": "array",
        "minItems": 1,
        "maxItems": 4,
        "items": { "$ref": "#/$defs/selector" }
      }
    },
    "selector": {
      "type": "object",
      "additionalProperties": false,
      "required": ["kind", "basis"],
      "properties": {
        "kind": {
          "enum": [
            "language", "framework", "manifest", "package_manager", "dependency",
            "build", "test", "database", "queue", "router"
          ]
        },
        "basis": { "enum": ["direct", "inferred"] },
        "key": {
          "type": "string",
          "minLength": 1,
          "maxLength": 160,
          "pattern": "^[a-zA-Z0-9@._/+*-]+$",
          "not": { "pattern": "\\s" }
        },
        "ecosystem": { "enum": ["npm", "composer", "go"] },
        "scope": { "enum": ["production", "dev", "peer", "optional", "indirect"] },
        "sourceFile": {
          "type": "string",
          "minLength": 1,
          "maxLength": 160,
          "pattern": "^[a-zA-Z0-9._-]+$",
          "not": { "anyOf": [{ "enum": [".", ".."] }, { "pattern": "\\s" }] }
        }
      },
      "allOf": [
        {
          "if": { "properties": { "kind": { "enum": ["router", "database", "queue"] } } },
          "then": { "anyOf": [{ "required": ["key"] }, { "required": ["sourceFile"] }] },
          "else": { "required": ["key"] }
        },
        {
          "if": { "properties": { "kind": { "const": "dependency" } } },
          "then": {},
          "else": { "not": { "anyOf": [{ "required": ["ecosystem"] }, { "required": ["scope"] }] } }
        }
      ]
    }
  }
}
```

### Field definitions

| Field | Ý nghĩa |
| --- | --- |
| `schemaVersion` | Bắt buộc. Số nguyên JSON `1`, không nhận chuỗi `"1"`. |
| `scope` ở root | `project` gắn với root `.`; `boundary` xét mỗi application, package, workspace hoặc root có fact được scanner gán. |
| `level` | Bắt buộc khi `scope: "project"`. Chọn tường minh `recommended` hoặc `optional`. Không có default. |
| `appliesWhen` | Bắt buộc khi `scope: "boundary"`. Mảng ngoài là OR, mảng trong là AND. Ví dụ `[[A, B], [C]]` nghĩa là `(A AND B) OR C`. |
| `recommendWhen` | Chỉ dùng cho boundary và chỉ xét sau khi `appliesWhen` khớp. `"on_match"` nâng ngay. Condition dùng cùng cấu trúc OR/AND. Bỏ trường này thì positive match cho `optional`. |
| Selector `kind`, `basis`, `key` | So sánh literal, case-sensitive với đúng các field trên cùng fact. `basis` luôn tường minh. Chỉ có `router`, `database`, `queue` được bỏ `key` khi có `sourceFile`. Ký tự `*` trong `key` nếu có là literal. |
| Selector `ecosystem`, `scope` | Chỉ cho `kind: "dependency"`, lọc theo trường tương ứng trên cùng fact. Nếu selector khai báo field mà fact thiếu thì fact không khớp. Selector `scope` ở đây là dependency scope, khác top-level scope. |
| Selector `sourceFile` | Tách basename theo dấu `/` và so khớp chính xác với ít nhất một `relativePath` của evidence ref mà fact đó trỏ tới. Nếu có `key`, yêu cầu cả `key` và `sourceFile`. Đây là filter trên evidence đã có, không mở file. Tên thư mục, selector text và basename của ref không liên quan không tạo match. |

Ví dụ hợp lệ cho một reusable skill được phân loại Optional là `{"schemaVersion":1,"scope":"project","level":"optional"}`. Mẫu này minh họa schema và không thuộc 19 file migration. Pattern trong JSON Schema chỉ kiểm tra ký tự hợp lệ của field. File metadata không có field cho task triggers, version ranges, negative conditions, công thức, regex/glob, code thực thi hoặc confidence scores.

## 2. Supported evidence vocabulary

Bảng đối chiếu với `shared/project-evidence.ts` và detector hiện tại. Các literal liệt kê ngoài 19 mẫu là ví dụ thực tế, không phải catalog allowlist đóng. Có thể dùng dependency name mới vì scanner xuất các khai báo hợp lệ từ manifest. Với các dạng detector có danh sách cố định, dùng đúng value có thể phát ra và chứng minh bằng fixture trước khi thêm rule.

| `kind` | Output được scanner hỗ trợ | `basis` và giới hạn |
| --- | --- | --- |
| `language` | `go` từ Go module; `php` từ Composer dependency `php`; filename extensions hỗ trợ `go`, `php`, `javascript`, `typescript`, `css`, `python`, `ruby`, `rust`, `java`, `kotlin`, `csharp`. | Module/Composer là `direct`. Filename là `inferred`. |
| `framework` | `react`, `nextjs`, `angular`, `laravel`, `wordpress-plugin`, `wordpress-theme`, `wordpress-child-theme`, `wordpress-block-theme`. | Tất cả `inferred`. JS/Angular/Laravel từ dependency/config evidence; WordPress từ header và marker liên quan. Giá trị `wordpress` đơn lẻ hiện không được phát. |
| `manifest` | Tên manifest được detector nhận diện như `package.json`, `go.mod`, `go.work`, `composer.json`, `angular.json`, `pnpm-workspace.yaml`, `pyproject.toml`. .NET dùng key extension `csproj`/`fsproj`/`sln`. | `direct` về sự hiện diện. File malformed vẫn có thể có manifest marker. |
| `package_manager` | `composer`, `go-modules`, `npm`, `pnpm`, `yarn`, `bun`. | `direct` từ manifest declaration; lockfile/workspace marker JS là `inferred`. Có thể có nhiều facts mâu thuẫn. |
| `dependency` | Tên package chính xác trong `package.json`, `composer.json`, `go.mod`, gồm cả `react-hook-form`, `formik`, `@tanstack/react-query`, `swr`, `@angular/forms` nếu thực sự khai báo. | `direct` về declaration; npm scopes production/dev/peer/optional, composer production/dev, Go production/indirect. Angular có thể phát `@angular/*` trên member khi detector đã liên kết declaration ở root. |
| `build` | Tool/marker như `vite`, `typescript`, `build-script`, `Makefile`, `github-actions`; Angular builder như `@angular/build/application` khi khai báo tương ứng. | `direct` về presence/declaration. Không phải build result. |
| `test` | Tool/marker như `vitest`, `test-script`, `phpunit-config`, `pestphp/pest` hoặc Angular test builder. `go-test` từ `_test.go`. | `direct` cho declaration/markers, `inferred` cho `go-test`. Không phải test result. |
| `router` | Go router module keys như `github.com/go-chi/chi/v5`; `nextjs-app`, `nextjs-pages`, `php-route-file`. | Go `direct` từ `go.mod`; Next và PHP `inferred`. Hai Next router facts có thể cùng tồn tại. |
| `database` | Go module keys như `github.com/jackc/pgx/v5`, npm/Composer markers như `pg`/`ext-pdo`, `database.php` từ config path, `migration-directory`. | `direct` từ dependencies hoặc presence của `config/database.php`; `migration-directory` là `inferred`. Không có runtime driver hoặc schema facts. |
| `queue` | Go module keys như `github.com/hibiken/asynq`, npm/Composer markers như `bullmq`/`laravel/horizon`, `queue.php` từ config path. | `direct` từ dependencies hoặc presence của `config/queue.php`. Không có runtime worker/backend facts. |

`coverage.unknown`, workspace membership, existing inventory, `ruleId`, `declaredAt`, version và target identity không phải fields cho selector v1. Task intent, test success, framework activation, HTTP standard-library usage, DB connector hoạt động, native form và Next cache/runtime behavior chưa được scanner xác nhận. Không tự thêm các keys giả định cho chúng.

## 3. Evaluation semantics

- **Project scope.** Áp dụng một lần ở root `.` với `level` đã ghi, reason `reusable_workflow`, reference tới companion file ở pinned SHA và root scope. Không yêu cầu technology fact. Bốn Common Skills bên dưới chọn `recommended` kể cả khi stack unknown hoặc scan partial. Điều này cho thấy workflow đáng cân nhắc ở cấp project; không mặc định chọn cài hoặc dùng cho task đang chạy.
- **Boundary scope.** Xét facts có `boundaryPath` bằng boundary đang đánh giá. Một nhóm AND chỉ đúng khi mọi selector khớp trong boundary đó, mỗi selector có thể khớp fact khác nhau. Không ghép các facts giữa siblings hoặc tự copy root facts xuống members. Ref có thể trỏ manifest của workspace root nếu scanner đã gán fact cho member và liên kết provenance hợp lệ. `recommendWhen` không bao giờ tạo match khi `appliesWhen` chưa khớp.
- **Verdicts.** Khớp base và điều kiện nâng mức cho `recommended` với `strong_project_match`. Khớp base khi không có điều kiện nâng mức cho `optional` với `project_match`; nếu có điều kiện nâng mức nhưng chưa quan sát được thì `additional_evidence_unobserved`. Không khớp base cho `unknown` với `partial_evidence` hoặc `no_supported_evidence` theo coverage. `not_applicable` được dành cho authoritative negative evidence chưa có ở v1, nên contract v1 không phát verdict này. Positive evidence đã xác nhận vẫn dùng được khi partial.
- **Giải thích.** Dùng refs của fact đã thực sự khớp cho cả base và promotion. Với `sourceFile`, liệt kê ref xác nhận filename đã khớp. Deduplicate refs và sắp xếp ổn định. Missing/invalid rule dùng catalog file reference nếu có và diagnostic; không tạo project ref giả. Một item cho mỗi Skill ID và giữ các positive boundary matches riêng. Tổng hợp theo thứ tự `recommended`, `optional`, `unknown` trong v1.
- **Task và installation.** `taskApplicability: "not_assessed"` cho mọi result. Inventory, duplicate occurrences, customization/mismatch và layout là thông tin riêng. Chúng không đổi scope, verdict hoặc cho phép overwrite/upgrade/merge/migrate.

## 4. Validation và resource limits

1. Exact root-level sidecar là regular blob trong cùng CatalogSnapshot, không lấy từ nested path, checkout hiện tại, external URL hay revision khác. Loader M2.1 tiếp tục thực thi giới hạn và blob-safety hiện có.
2. Byte length tối đa **8.192 bytes/file**. Yêu cầu UTF-8 hợp lệ, không BOM, một JSON object, JSON whitespace chuẩn; không comment, trailing comma, duplicate object keys ở bất kỳ cấp nào hoặc YAML syntax. Duplicate keys kiểm tra theo tên đã decode, kể cả escape biểu diễn cùng key. Parser chuẩn một mình có thể chấp nhận duplicate keys theo last-write-wins, nên ingestion cần kiểm tra riêng trước khi dùng object đã parse. Strict shape như mục 1; không bỏ qua unknown properties. Dùng string comparisons nguyên dạng, không trim hoặc normalize nội dung selector.
3. Tối đa **4 OR groups/condition**, **4 selectors/group**. Boundary rule tối đa 32 selector positions khi cả hai conditions đạt giới hạn. Key/sourceFile tối đa 160 ký tự và chỉ các ký tự trong schema. Kế thừa tối đa **512 skills**, **64 boundaries**, scanner evidence budget **256 KiB**; đề xuất response limit **512 KiB** và một lượt recommendation/installation như kế hoạch.
4. Missing file trả `unknown/missing_applicability`. File hiện diện nhưng không hợp lệ, gồm oversize, sai encoding hoặc duplicate keys, trả `unknown/invalid_applicability` cho skill đó. Object JSON hợp lệ với `schemaVersion` là số nguyên khác 1 trả `unknown/unsupported_rule_version` trước validation shape v1. Defect của sidecar không vô hiệu hóa các skill khác đã load hợp lệ.
5. Shape hợp lệ với literal chưa được quan sát chỉ cho no-match. Authoring review phải kiểm tra detector và fixture để tránh typo hoặc vocabulary chưa hỗ trợ. Khi thực hiện migration, không thêm semantic extension vào v1 để làm một file match.

## 6. Compatibility và versioning

- Companion là dữ liệu trong thư mục skill. Giữ nguyên Agent Skills frontmatter, body, license và source notices. Consumer Agent Skills có thể bỏ qua file; Catalog Loader cũ thấy supporting file thường. Với consumer copy nguyên thư mục, file có thể đi theo. Quyết định có lọc package ở Preview hoặc Apply thuộc milestone sau.
- `schemaVersion` version riêng của payload, không phải tag release catalog. Thêm skill dùng vocabulary đang hỗ trợ không yêu cầu thay đổi engine. Sửa rule theo schema v1 giữ schema version 1 nhưng tạo catalog commit mới. Xét theo versioning Project-Skills, thay đổi applicability ảnh hưởng trigger/project fit nên đề xuất bump minor cho lần release migration nếu catalog phát hành tag. Chỉ chọn tag hoặc full SHA đã duyệt; không auto-update settings.
- Thay cấu trúc/semantics, thêm selector field hoặc đổi meaning của vocabulary cần review contract và consumer trước. Consumer v1 trả diagnostic cho schema version chưa hỗ trợ. Catalog revision cũ vẫn đọc được, mọi skill thiếu metadata có verdict `unknown`. Dạng `{"schemaVersion":1,"scope":"project"}` từng minh họa trong kế hoạch nháp bị thay bằng dạng bắt buộc `level`.

## 7. Catalog migration instructions

1. Chỉ làm migration sau khi được phê duyệt riêng. Làm việc trong Project-Skills và đối chiếu checkout với baseline hoặc lập danh sách sai khác trước khi authoring. Xác nhận 19 slug ở mục 5 khớp tên thư mục và `name` hiện có. Nếu catalog đã thêm/đổi skill, đưa phần sai khác qua review trước khi tạo rule mới.
2. Tạo đúng 19 file từ mục 5. Writer nên dùng UTF-8, LF và newline cuối file. Không sửa các `SKILL.md`, `SOURCES.md`, license hoặc workflow. Không có file global manifest.
3. Validate từng file bằng schema mục 1 và checks mục 4. Kiểm tra số slug đã migrate, exact path, không duplicate JSON keys và diff trong repo. Dùng fixtures độc lập để chứng minh selector thật sự có thể match từ scanner.
4. Ghi format và versioning trong `docs/skill-standard.md` của Project-Skills nếu đã được duyệt cùng migration. Release note ghi 19 sidecar files, Common project-level recommendation và cách đọc revision cũ. Chốt commit SHA hoặc tag upstream chỉ sau khi review và theo quyền Git riêng. Dùng ref đó cho integration acceptance sau khi engine được triển khai.

## 8. Acceptance criteria

**Đối chiếu trong lượt tài liệu.** Validator Draft 2020-12 chấp nhận cả 19 mẫu và mẫu project Optional, đồng thời từ chối 7 trường hợp shape sai. Danh sách 19 mẫu khớp chính xác Git tree catalog. Fixture tạm chạy qua `ProjectScanner` hiện tại tạo được fact cho cả 32 vị trí selector trong 15 rule boundary, gồm cả hai Next routers, hai Laravel config markers và declaration `@angular/forms` của Angular workspace root được scanner gán cho member. Đây là kiểm chứng vocabulary và provenance, chưa phải nghiệm thu Recommendation Engine.

- Contract và 19 file mẫu parse được, khớp exact schema và mỗi mẫu map đúng một skill của catalog baseline. Bốn Common Skills trả `recommended` tại root; một mẫu project `optional` ngoài catalog chứng minh schema hỗ trợ cả hai mức. Cả hai không làm task applicability khác `not_assessed` và không tự chọn cài.
- Authoring check bao phủ từng selector path. Go language-only và framework anchors thiếu promotion vẫn ra Optional khi quy định. Go promotion chỉ dùng refs từ `go.mod`. Cả hai Next routers, Angular root declarations đã liên kết, Laravel dependency/config alternatives và WordPress headers có fixture. PHP/JS dependencies cùng boundary không giả làm Go declarations.
- Invalid shape, duplicate keys, unsupported version, missing file và oversize đều dẫn đến đúng diagnostic và Unknown cho skill liên quan. Partial hoặc complete thiếu evidence không tự tạo Not applicable.
- OR/AND và sourceFile không vượt scope. Test monorepo có ít nhất một sibling không được kế thừa evidence, và một skill khớp nhiều boundaries vẫn chỉ có một item. Test inventory state độc lập với applicability. Khi triển khai engine, từng reason trace được tới catalog/evidence refs hợp lệ.
- Catalog cũ vẫn mở được; catalog fixture có sidecar cũng load được bằng M2.1 như supporting file. Một skill mới dùng vocabulary hiện có không cần sửa engine core. Runtime migration acceptance sẽ dùng một pinned revision riêng sau review. Giữ toàn bộ regression tests khi triển khai.

Dừng tại contract. Chờ review trước khi triển khai engine hoặc thực hiện migration Project-Skills.
