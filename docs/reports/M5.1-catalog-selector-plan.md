## 3. Proposed Settings and RPC Contracts

### 3.1 Host Settings (`shared/catalog-settings.ts`)

Keep `id: "catalog"`, `scope: "host"`, `version: 1`, and keep **`catalogRef`** as the single authoritative pinned revision consumed by `CatalogLoader`, `recommendation.evaluate`, `preview.*`, `PreviewManifest.savedCatalogRef`, and `apply.create.v1`. Add optional metadata fields that remain backward-compatible with existing `{ catalogRef }` JSON:

```ts
export const catalogSelectionModeSchema = z.enum([
  "latest_stable",
  "specific_version",
  "custom",
]);

export const stableSemverTagSchema = z
  .string()
  .regex(/^v(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)$/);

export const catalogSettingsSchema = z.object({
  // Authoritative pinned revision. All M5.1 UI saves write a lowercase 40-char commit SHA here.
  // Legacy host configs with "" or a tag name still parse without breaking.
  catalogRef: catalogRefSchema.default(""),
  selectionMode: catalogSelectionModeSchema.optional(),
  selectedTag: catalogRefSchema.optional(),
}).superRefine((val, ctx) => {
  if (val.catalogRef === "" && (val.selectionMode !== undefined || val.selectedTag !== undefined)) {
    ctx.addIssue({ code: "custom", message: "Selection metadata requires a pinned catalogRef." });
  }
  if (val.selectionMode === "latest_stable" || val.selectionMode === "specific_version") {
    if (!/^[a-f0-9]{40}$/.test(val.catalogRef)) {
      ctx.addIssue({ code: "custom", message: "Managed modes require a pinned 40-character commit SHA." });
    }
    if (!val.selectedTag || !stableSemverTagSchema.safeParse(val.selectedTag).success) {
      ctx.addIssue({ code: "custom", message: "Managed modes require a valid stable SemVer tag." });
    }
  }
});
```

- `catalogSettingsSchema.parse({})` still yields `{ catalogRef: "" }`.
- Existing `{ catalogRef: "<40-hex>" }` and `{ catalogRef: "<legacy-tag>" }` continue to parse with `status: "ready"`.

### 3.2 Daemon RPC Contracts (`shared/catalog.ts`, `shared/rpc.ts`)

`catalog.load` remains **unchanged**. Add two strictly read-only daemon RPCs (neither mutates host settings or target files):

1. **`catalog.releases`** (`catalogReleasesRpc`)
   - **Input:** `z.strictObject({ refresh: z.boolean().optional() })`
   - **Output (discriminated union on `status`):**
     - `ready`:
       - `source: typeof catalogSource`
       - `settingsRevision: string`
       - `active`: `{ catalogRef: string; selectionMode?: CatalogSelectionMode; selectedTag?: string; isPinnedSha: boolean }`
       - `releases`: `Array<{ tag: string; commitSha: string }>` (stable SemVer tags sorted descending, bounded to `100` items)
       - `latestStable`: `{ tag: string; commitSha: string } | null`
       - `updateAvailable`: `boolean` (`true` iff `latestStable !== null`, `active.catalogRef !== ""`, and `latestStable.commitSha !== active.catalogRef.toLowerCase()`)
       - `checkedAt: number` (wall-clock epoch ms)
       - `cached: boolean`
     - `error`:
       - `code: CatalogErrorCode`
       - `settingsRevision?: string`

2. **`catalog.resolve`** (`catalogResolveRpc`)
   - **Input (discriminated union on `mode`):**
     - `z.strictObject({ mode: z.literal("latest_stable") })`
     - `z.strictObject({ mode: z.literal("specific_version"), tag: stableSemverTagSchema })`
     - `z.strictObject({ mode: z.literal("custom"), ref: catalogRefSchema.refine((r) => r.length > 0) })`
   - **Output (discriminated union on `status`):**
     - `ready`:
       - `source: typeof catalogSource`
       - `mode: CatalogSelectionMode`
       - `requestedRef: string`
       - `resolvedTag?: string` (set for `latest_stable`, `specific_version`, and custom tag inputs; omitted for custom SHA inputs)
       - `commitSha: string` (full lowercase 40-char commit SHA)
       - `skillCount: number`
     - `error`:
       - `code: CatalogErrorCode` (including `no_stable_releases` if approved — see Section 10)
       - `diagnostics?: CatalogDiagnostic[]`

## 4. Revision Resolution, Pinning, Caching & Invalidation Lifecycle

```mermaid
flowchart LR
  U["User selects mode / version"] --> R["RPC: catalog.resolve"]
  R --> L["Daemon: ls-remote (if latest_stable) + CatalogLoader.load(ref)"]
  L -->|Invalid / unavailable / malformed| F["Fail closed: keep existing settings"]
  L -->|Valid commit + catalog tree| C["Warm CatalogLoader SHA cache"]
  C --> S["Client: settings.save(catalogRef=SHA, mode, tag, expectedRevision)"]
  S -->|Revision conflict| F2["Fail closed: prompt Reload settings"]
  S -->|Saved (new settingsRevision)| I["Scope changes -> invalidate Scan, Selection, Preview & Receipts"]
  I --> SC["Scan & Recommend (uses pinned SHA + hits SHA cache)"]
```

1. **Resolution & Validation Before Pinning:**
   - `catalog.resolve` resolves the requested mode/ref on the daemon:
     - `latest_stable`: performs a fresh `CatalogGit.listTags()`, selects the highest stable SemVer tag (fails closed if none exists), then runs `CatalogLoader.load(tag)`.
     - `specific_version`: validates SemVer syntax, then runs `CatalogLoader.load(tag)`.
     - `custom`: validates `catalogRefSchema` (non-empty, ≤256 bytes), then runs `CatalogLoader.load(ref)`.
   - `CatalogLoader.load()` fetches strictly via `refs/tags/<tag>` or exact 40-char SHA, verifies `cat-file -t === "commit"`, validates the entire `skills/` tree and `SKILL.md` frontmatter (`discover` + `describeCatalog`), and inserts the validated `CatalogSnapshot` into its 2-entry in-memory LRU keyed by `commitSha`.
2. **Immutable Pinning Before Scan:**
   - Only after `catalog.resolve` returns `status: "ready"` does the client call `settings.save({ catalogRef: resolved.commitSha, selectionMode, selectedTag }, settings.revision)`.
   - Because `catalogRef` is now the exact 40-char `commitSha`, all downstream calls (`catalog.load`, `recommendation.evaluate`, `preview.providers.v2`, and `apply.create.v1` revalidation) hit the immutable SHA cache and cannot drift even if a remote tag is later moved or deleted.
3. **Release List Caching & Update Detection:**
   - `CatalogReleaseCache` (in-memory only, cleared on `dispose()`) caches `git ls-remote --tags` results for **60 seconds** (monotonic clock `performance.now()`) with single-flight deduplication.
   - `catalog.releases({ refresh: true })` bypasses the 60 s TTL subject to a **5-second** minimum cooldown (coalescing rapid clicks).
   - Update detection is purely informational (`updateAvailable: true`): it **never** modifies `catalogSettings` or replaces the active pinned SHA.
4. **Invalidation Lifecycle (Preserving All M4 Guarantees):**
   - Editing draft mode/selection in the UI does not modify `catalogSettings` and does not disturb an active scan or preview until the user explicitly confirms **Pin** / **Update**.
   - Saving a new pinned SHA advances `settings.revision` and updates `settings.values.catalogRef`:
     - During save, `settings.saving === true` disables **Scan & Recommend** and **Preview Changes**.
     - On save completion, `RecommendationRun`'s `scope` (`[hostId, generation, directory, revision, ref]`) changes → previous recommendations become `stale`, `selectedSkillIds` clear, and `PreviewRun` / `FixtureApprovalPreview` unmount and discard any reviewed receipt.
     - Daemon-side `recommendation.evaluate`, `preview.providers.v2`, and `apply.create.v1` revalidation continue to enforce `settingsRevision` + `catalogCommitSha` + `manifestDigest` checks with zero changes.

## 7. Failure Scenarios and Security Analysis

| Scenario | Expected Fail-Closed Behavior |
| --- | --- |
| **No stable tags on `anmeo2204/project-skills`** (current state) | `catalog.releases` returns `latestStable: null, releases: [], updateAvailable: false`. `catalog.resolve({ mode: "latest_stable" })` returns error (`no_stable_releases` / `revision_unavailable`). **Never falls back to `main` HEAD.** |
| **Branch name entered in Custom mode** (e.g., `main`) | `CatalogGit.resolve` fetches only `refs/tags/main`. Absent tag → `revision_unavailable`. |
| **Tag points to blob/tree or malformed catalog** | `CatalogLoader.load()` rejects non-commit objects and invalid `skills/` trees (`invalid_catalog` with bounded diagnostics). Settings are **not** saved. |
| **Mutable tag force-moved between list & resolve (TOCTOU)** | `catalog.resolve` fetches and validates the actual commit and pins its 40-char SHA. All subsequent Scan/Preview/Apply steps bind that immutable SHA. |
| **SSH auth failure / untrusted host key / offline / timeout** | Hardened `CatalogGit` (`BatchMode=yes`, `StrictHostKeyChecking=yes`, `GIT_TERMINAL_PROMPT=0`, `GIT_ALLOW_PROTOCOL=ssh`, process-group `SIGKILL`) returns typed `auth_failed` / `network_error` / `timeout`. Active pinned `catalogRef` is preserved untouched. |
| **Huge tag list / remote output DoS** | `ls-remote` stdout capped at `256 KiB`, timeout `10 s`, RPC response capped at `100` stable releases, single-flight coalescing + `5 s` refresh cooldown. |
| **Git option / command injection** | `spawn("git", args, { shell: false })` with `--` before remote; tag names validated by `catalogRefSchema` (rejects leading `-`, whitespace, control chars, `refs/`). |
| **Concurrent settings edit from another client** | `settings.save(values, settings.revision)` fails with optimistic concurrency conflict; user reloads settings. |
| **Apply / Relay / Enrollment safety boundary** | Zero edits to native writer, enrollment policy, Relay policy, compatibility matrix, or Apply coordinator. |

## 9. Acceptance Criteria & Regression Test Plan

### Acceptance Criteria
- **AC1 (Modes):** Users can select **Latest Stable**, **Specific Version**, or **Advanced Custom Revision** without manually typing a SHA in normal workflows.
- **AC2 (Daemon Resolution & Pinning):** Every UI selection resolves and validates the catalog on the daemon (`catalog.resolve`) and saves a full lowercase 40-char `commitSha` to `catalogRef` before Scan is enabled.
- **AC3 (Fail-Closed):** Zero stable tags, nonexistent tags/SHAs, branch names (e.g., `main`), non-commit tags, malformed catalogs, and SSH/network errors all fail closed without modifying existing settings and without falling back to `main` HEAD.
- **AC4 (Update Detection):** Publishing a newer SemVer tag surfaces `updateAvailable: true` in the UI without altering the active pinned `catalogRef` until the user explicitly clicks **Pin**.
- **AC5 (M4 Safety Preservation):** Changing the pinned revision advances `settingsRevision`, invalidates active recommendations/selections/previews/receipts, and passes all existing M4 Preview v2 and Apply revalidation checks unchanged.
- **AC6 (Compatibility & Cross-Platform):** Existing host settings (`""`, SHA, legacy tag) load cleanly; shared React Native UI renders and operates on both Desktop and Mobile (`compact: true`) with zero AI/SLP/Kanbanly dependencies.

### Regression Test Plan
1. `npm run verify:sdk-manifest` (unchanged build-time manifest & writer binding).
2. `npm run typecheck`.
3. `npm test` — all existing suites (`contracts`, `catalog-loader`, `project-scanner`, `recommendation-engine`, `canonical-preview`, `provider-adapters`, `preview-receipt`, `native-writer`, `apply-journal`, `m4p1`, `m4p2`, `foundation-screen`, `scan-ui`, `preview-ui`) plus new `tests/catalog-releases.test.mjs`:
   - Annotated (`^{}`) vs lightweight SemVer tags, numeric SemVer sorting (`v0.10.0 > v0.2.0`), pre-release/non-SemVer exclusion.
   - Zero-tag repo → `latestStable: null`, `catalog.resolve({ mode: "latest_stable" })` fails closed even when `main` has valid skills.
   - Force-moved tag between list and resolve pins the actual fetched commit SHA.
   - Cache TTL (60 s), `refresh: true` cooldown, single-flight coalescing, and `CatalogLoader` SHA cache warm-up (zero duplicate Git fetch on subsequent `catalog.load`).
   - UI tests for all 3 modes, update banner without auto-replacement, legacy tag upgrade flow, compact/mobile rendering, and scan/preview/receipt invalidation upon pinning a new revision.
