## Journal retention và tìm lại operation

- `completed`, `failed_before_write` và `partial_failure` giữ 24 giờ tính từ timestamp durable lúc settlement. Với record từ M4.4/M4.5, dùng mtime của file record do atomic settlement tạo. Status coi record hết hạn là `outcome_unknown`. Đợt admission tiếp theo prune file hết hạn dưới cùng coordinator lock và fsync journal directory. Home rảnh có thể còn file hết hạn cho tới lượt admission tiếp theo.
- `accepted`, `preflight`, `writing` và `recovery_required` được giữ. Cap giữ nguyên 64 records và 2 MiB mỗi record. Exact retry trước hạn trả record cũ cả sau restart, vẫn kiểm payload và binding. Hết hạn record không gia hạn approval, không tạo lại operation tự động và không sửa target.
- Trong cùng Desktop profile, mở lại **Approval Fixture** trên host gốc rồi xem **Apply Operations**. Tracker fixture lưu host ID, operation ID và plan digest trong local storage có key theo installation slot. Nó ghi metadata trước khi gọi Apply và từ chối gửi nếu lưu thất bại. Sau reload, record khôi phục ở trạng thái chưa xác định và chỉ gọi `apply.status.v1` trên host/slot khớp. Không lưu preview token, nonce, approval, plan, bytes, target path hay ledger. Người dùng có thể đối chiếu operation ID hiển thị. Kết quả vẫn do journal quyết định. 
- Full journal, exact retry sau restart, expiry 24h, prune và fill lại được kiểm bằng test clock và daemon thật. Lượt daemon dùng records synthetic để lấp cap, chỉnh timestamp terminal của fixture để đi qua mốc 24 giờ, rồi xác nhận journal-full giữ nguyên target, exact retry phục hồi trước expiry và recovery record vẫn còn. ## Support matrix và phạm vi release

| Môi trường / đường đóng gói | Kết luận |
| --- | --- |
| macOS 27.2.1 (26B131), arm64, local APFS case-insensitive, Paseo Desktop/daemon 0.17.5, SDK client/plugin/protocol 0.17.4 | Phạm vi fixture đã kiểm. Native gate vẫn kiểm OS, architecture, local APFS và case mode. |
| APFS case-sensitive, network/FUSE/cloud, x64, Linux và Windows | Ngoài phạm vi Apply đã kiểm. |
| Directory plugin từ source với dependencies 0.17.4 | Đường runtime dùng để kiểm fixture. Native executable nhúng base64 trong bundle, extract riêng, kiểm SHA-256/version và chữ ký build. |
| Phát hành npm/Git/managed install, update, notarization và quarantine delivery | Chưa có evidence release của writable package. |

SDK 0.17.4 chuyển `paseo` vào RPC handler, thiếu caller principal. Approval bind theo host + installation instance của receipt, Status bind theo host + slot ổn định đã cấu hình. Operation ID là opaque lookup key trong boundary đó. Không thể gán thao tác cho một tài khoản hay khẳng định chính người đã review gửi RPC. Shared lock chỉ serialize các writer của cùng daemon namespace. Pinned directory handle vẫn có cửa sổ rename đã nêu ở M4.3, và direct create có thể để lại file dở hoặc ownership chưa xác minh.

**NO-GO cho bật Apply production.** Product chưa có writable registration và artifact đã kiểm vẫn là fixture-only. Directory bundle Preview-only có thể tiếp tục dùng trong phạm vi đã kiểm. Quyết định GO cho Apply cần nghiệm thu artifact cài đặt dự kiến ship và chốt boundary với release owner trên support matrix thực tế. Retention và tracking của fixture đã hoàn tất trong phạm vi báo cáo.
