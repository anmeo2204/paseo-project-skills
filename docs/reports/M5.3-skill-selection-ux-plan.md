## Approved Decisions & Required Corrections (Applied)

- **D1 (Grouping Modes):** Support grouping by `Applicability` (default), `Boundary`, and `Observed Status` using existing metadata only (zero catalog schema changes, zero hardcoded framework categories or skill ID prefixes).
- **D2 (Observed-File Semantics):** Use explicit observed-file labels (`Observed in project`, `Multiple copies observed`, `Not observed`, `File state unverified`) and a non-activation disclaimer.
- **D3 (Auto-Reveal Matching Unknown):** Automatically reveal matching `Unknown` skills during search or relevant filtering without mutating the user's saved `showUnknown` collapse state.
- **D4 (M5.2 Follow-Up Tests):** Include targeted mid-refetch (`isRefetching`) and delayed target-A provider snapshot regression tests in `tests/project-provider-ux.test.mjs`.
- **P1 (Bulk Selection Scope):** `Select Recommended` adds recommended skills across the complete scan result (not only visible items), displays the count of additional skills to be selected (`+N`), preserves manual selections, and never selects `optional` or `unknown` skills. `Clear Selection` clears the complete skill selection while preserving providers.
- **P2 (Hidden Selection Visibility):** Count selected skills hidden by search, filters, and collapsed groups; `Show Selected` resets conflicting filters and reveals all selected skills (including selected `Unknown` skills). Selection summary displays actual target provider names (e.g., `Codex, Kiro`) and preserves canonical-only semantics when no providers are selected.
- **P3 (Selection Invalidation):** Search, filtering, grouping, and disclosure changes never mutate selection or invalidate Preview. No-op selection actions do not advance `selectionGeneration`; every real selection mutation (including batched A → B → A) advances `selectionGeneration` and invalidates stale Preview and Approval state.
- **P4 (Catalog Scalability):** Benchmark synthetic catalogs of `19`, `100`, and `512` skills for filtering, grouping, rendering, and selection responsiveness on Desktop and compact Mobile layouts without premature virtualization.

## Objective

Improve Skill Selection and Recommendation UX for both Desktop and Mobile so users can efficiently search, filter, group, inspect evidence, understand observed existing files, and review a compact selection summary before Preview — scaling cleanly as the catalog grows while preserving all M4, M5.1, and M5.2 safety guarantees.

## 2. Existing Catalog and Recommendation Metadata Capabilities

Every M5.3 UX capability can be built **purely from existing metadata without any catalog schema changes or hardcoded framework tables**:

| Capability | Existing Data Source | Notes |
| --- | --- | --- |
| **Search** | `item.skillId`, `catalog.skills[].metadata.name`, `catalog.skills[].metadata.description` | All already present in `CatalogSnapshotDescriptor` and `RecommendationItem`. |
| **Primary Grouping (Established Taxonomy)** | `item.applicability` (`recommended`, `optional`, `unknown`) | Deterministic output of `evaluateRecommendation()`. |
| **Secondary Grouping (Generic, Zero Hardcoding)** | `item.matches[].boundaryPath` & `reasons[].code === "reusable_workflow"` (for **By Scope / Boundary**); `item.inventory.state` (for **By Observed Inventory**) | Derived strictly from existing scanner/engine fields; no framework names or slug prefixes (`go-*`, `react-*`) hardcoded in UI. |
| **Filtering** | `item.applicability`, `selected.includes(item.skillId)`, `item.inventory.state`, `item.inventory.occurrences[].flags` | Supports filtering by applicability/recommendation, selection state, and observed installation state. |
| **Concise & Expandable Evidence** | `item.reasons`, `item.matches`, `result.evidence` (`EvidenceRef[]`), `catalog_file` (`path`, `blobSha`) | Already structured with stable IDs and traceable provenance. |
| **Observed Inventory Semantics** | `item.inventory.state` + `occurrences[]` (`relativePath`, `layout`, `boundaryPath`, `match`, `flags`) | Already distinguishes `confirmed` vs `candidate` matches and review flags (`metadata_mismatch`, `malformed`, `unreadable`, `possible_customization`). |

**Conclusion on Catalog Schema:** No catalog schema or `applicability.json` change is needed for M5.3. If future catalogs grow large enough to require explicit domain categories (e.g., `category` or `tags` in `SKILL.md` frontmatter), that should be proposed as an additive, backward-compatible catalog contract change in a later milestone rather than inferred from slug prefixes in generic UI.

## 3. Proposed Desktop and Mobile UI

All UI uses shared React Native + `@getpaseo/plugin/client/ui` primitives (`View`, `Text`, `Pressable`, `Icon`, `Input`, `Action`, `Detail`, `Disclosure`) with responsive spacing (`compact: boolean` passed from `FoundationScreen` → `RecommendationRun` → `RecommendationResults`).

### 3.1 Top Toolbar (Search, Filters, Group-By, Bulk Actions)
1. **Search Input:**
   - `Input` (`accessibilityLabel="Search skills"`, placeholder `"Search by name, ID, or description…"`) + `Clear search` button when non-empty.
2. **Compact Filter Bar** (`flexDirection: "row", flexWrap: "wrap", gap: 8`, `minHeight: 36` touch targets):
   - **Applicability:** `All` | `Recommended` | `Optional` | `Unknown`
   - **Selection:** `All` | `Selected` | `Unselected`
   - **Observed files:** `All` | `Observed` (`present` or `multiple_occurrences`) | `Not observed` | `Needs review` (`multiple_occurrences`, `unknown`, or any occurrence `flags.length > 0`)
   - **Reset filters** button shown whenever search or any non-default filter is active.
3. **Group-By Selector** (compact wrapped pills):
   - `By Applicability` *(default)* | `By Boundary` | `By Observed Status`
4. **Explicit Bulk Actions:**
   - **Select Recommended** (additive: adds all `recommended` skills across the full scan result; never selects `optional` or `unknown`; disabled when all recommended skills are already selected).
   - **Clear Selection** (clears `selected` to `[]`; preserves target providers; disabled when `selected.length === 0`).

### 3.2 Skill List & Compact Rows
- **Group Headers:** Show `<Group Title> (<visibleCount>)` (or `<visibleCount>/<totalCount>` when filtered).
  - Under `By Applicability`, `Unknown` remains collapsed by default (`showUnknown = false`). When an active search query or explicit filter (`Unknown`, `Selected`, `Observed`, `Needs review`) matches items inside `Unknown`, matching `Unknown` items are surfaced automatically (with a clear `"Showing matching Unknown skills"` note) without mutating the user's manual `showUnknown` preference once filters are cleared.
- **Compact `SkillRow` Card:**
  - Checkbox `Pressable` (`accessibilityRole="checkbox"`, `accessibilityLabel="Select <skillId>"`, `minHeight: 36`) + bold `skillId`.
  - Compact metadata line: `<Applicability> · <Observed status>` (plus boundary count when `matches.length > 0`, and concise warning flags when present).
  - Concise description + 1-line primary reason summary.
  - Expandable `Disclosure` (`Details for <skillId>`) showing full per-boundary evidence, catalog rule `path · blobSha`, and `Existing skill inventory` occurrences.
- **Empty Filtered State:** `"No skills match the current search and filters."` + **Reset filters** button.

### 3.3 Compact Selection Summary Before Preview
Placed at the bottom of `RecommendationResults` (directly above `Preview Changes`):
- `Selected skills: N` with applicability breakdown (e.g., `2 recommended · 1 optional · 0 unknown`).
- Hidden-selection indicator when active search/filters hide any currently selected skills: e.g., `1 selected skill is hidden by current filters.` (with quick **Show selected** filter shortcut).
- Observed-overlap indicator when any selected skill already has observed files in the project: e.g., `1 selected skill has existing files observed (Preview will check for unchanged/conflict).`
- Active target provider summary (`Target providers: K` or `Target providers: none (canonical .agents/skills only)`).
- Explicit non-authorization reminder: *"Selection records intent only. Review Preview Changes before approving any create-only writes."*

## 4. Search, Grouping and Filtering Behavior

- **Search Matching:** Pure function `filterAndGroupSkills(...)` in a dedicated client helper (`client/skill-selection.ts`). Trims and lowercases query; matches if `skillId`, `metadata.name`, or `metadata.description` contains the query substring.
- **Filter Composition:** Logical **AND** across Search, Applicability filter, Selection filter, and Observed status filter.
- **Deterministic Ordering:** Within every group, skills are sorted lexicographically by `skillId` (matching existing engine/UI determinism).
- **Grouping Modes (Generic, Metadata-Driven):**
  1. **`applicability` (default):** `Recommended` → `Optional` → `Unknown`.
  2. **`boundary`:**
     - `Project-wide` (skills with a `.` match having `reusable_workflow`)
     - Each distinct matched `boundaryPath` sorted lexicographically (a skill matching multiple boundaries appears under its primary/first matched boundary with a `+N boundaries` badge to avoid duplicate checkboxes in the same render!)
     - `No boundary match` (skills with `matches.length === 0`)
  3. **`inventory`:** `Observed in project` (`present` / `multiple_occurrences`) → `Not observed` → `Installation state unknown`.
- **Single-Checkbox Invariant:** Every skill renders at most **once** in the list across all grouping modes so checkbox state, accessibility labels, and `Select <skillId>` controls remain unique and unambiguous.

## 5. Selection and Invalidation Lifecycle

- **Ownership:** `selected: string[]` and `selectionGeneration` stay owned by `RecommendationRun` (reset on rescan, host switch, target change, or catalog settings change).
- **View State Isolation:** `search`, `applicabilityFilter`, `selectionFilter`, `inventoryFilter`, `groupBy`, and `showUnknown` live inside `RecommendationResults` (keyed by `intent.recommendationRequestId`, so they reset cleanly on a new scan).
- **Preservation Across View Changes:** Changing search text, toggling filters, changing `groupBy`, or expanding/collapsing groups or row details **never** modifies `selected` and **never** bumps `selectionGeneration`.
- **Invalidation on Selection Mutation:** Toggling any skill checkbox, clicking **Select Recommended**, or clicking **Clear Selection** updates `selected` and increments `selectionGeneration`, which immediately updates `SelectionIntentV1` and invalidates any in-flight or completed `PreviewRun` / `FixtureApprovalPreview` receipt.

## 6. Observed Installation Status Semantics

To prevent users from confusing scanned files with provider activation or successful installation:
- **User-Facing Labels:**
  - `present` → `"Observed in project"` (instead of ambiguous `"Present"`)
  - `multiple_occurrences` → `"Multiple copies observed"`
  - `not_observed` → `"Not observed"`
  - `unknown` → `"File state unverified"`
- **Explicit Disclaimer:** Displayed whenever at least one skill has `inventory.state !== "not_observed"`:
  > *"Observed status reflects files found during the read-only scan only. It does not confirm provider discovery, activation, or precedence, and Safe Apply never overwrites existing files."*
- **Non-Blocking:** Observing an existing file does not disable selecting that skill (a user may still select it to verify `unchanged` status or inspect a `conflict` in read-only Preview, or to plan Kiro derived copies when canonical matches).

## 8. Failure Scenarios and Safety Analysis

| Scenario | Expected Behavior |
| --- | --- |
| **Partial scan or legacy catalog without `applicability.json`** | All skills appear under `Unknown` with existing partial/missing-metadata banners and `Scan and catalog details`. Search, selection, and `Clear Selection` work normally; `Select Recommended` is disabled (never auto-selects `Unknown`). |
| **Selected skills hidden by active search or filters** | Selection is preserved in `RecommendationRun`; the selection summary explicitly reports how many selected skills are hidden by current filters and offers a 1-click `Show selected` shortcut so users never accidentally preview unseen skills. |
| **Skill matches multiple boundaries in `By Boundary` mode** | Assigned deterministically to its primary (lexicographically first) matched boundary with a `+N more boundaries` indicator — never renders duplicate checkboxes for the same `skillId`. |
| **Observed existing skill selected for Preview** | Selection is allowed; summary warns that existing files were observed; Preview deterministically reports `unchanged` or `conflict` (blocking Apply on any conflict); Safe Apply never overwrites existing files. |
| **Selection changed while Preview/Approval is active** | Toggling any skill, clicking `Select Recommended`, or clicking `Clear Selection` advances `selectionGeneration`, immediately discarding Preview results and Approval receipts. Searching/filtering alone does not spuriously discard Preview. |
| **Rescan, target change, host switch, or catalog pin change** | `RecommendationResults` remounts under new `recommendationRequestId` (or unmounts), resetting search/filter/group view state and clearing stale selections. |
| **Catalog growth (e.g., 50–512 skills)** | Pure client-side filtering and grouping remain O(N log N) over the bounded `<= 512` skill catalog limit with zero network calls or extra daemon load. |

## 9. Acceptance Criteria and Regression Test Plan

### Acceptance Criteria
- **AC1 (Search):** Users can search skills by `skillId`, `name`, or `description` and clear search cleanly; matching `Unknown` skills are discoverable without manually hunting through collapsed sections.
- **AC2 (Grouping & Filtering):** Users can group by `Applicability` (default), `Boundary`, or `Observed Status` without hardcoded framework rules, and filter by applicability, selection, and observed status with clear empty-state and `Reset filters` recovery.
- **AC3 (Manual Selection Preservation):** Manual selections survive search, filter toggles, group-by switches, and disclosure expand/collapse; hidden selected skills are explicitly surfaced in the summary.
- **AC4 (Bulk Actions):** `Select Recommended` adds only `recommended` skills (preserving manual selections, never selecting `optional`/`unknown`); `Clear Selection` clears skills while preserving target providers.
- **AC5 (Observed Semantics & Evidence):** Concise evidence and expandable full provenance work on Desktop and Mobile; observed files are explicitly labeled as read-only scan observations (never provider activation).
- **AC6 (Summary & Safety):** Compact selection summary appears before Preview with applicability/observed/provider counts; selection mutations invalidate Preview & Approval; all M4, M5.1, and M5.2 invariants remain untouched.

   - UI tests for Desktop (`compact: false`) and Mobile (`compact: true`) rendering.
   - Manual selection preservation across search → filter → group-by → clear filters.
   - `Select Recommended` (never selects `optional`/`unknown`) and `Clear Selection` (preserves providers).
   - Observed-file disclaimer and non-activation wording.
   - Selection mutation invalidating active Preview/Approval vs search/filter NOT spuriously invalidating Preview.

## 10. Decisions Requiring User Approval

1. **Grouping Modes (Without Catalog Schema Changes):**
   - **Recommended:** Keep **By Applicability** (`Recommended` / `Optional` / `Unknown`) as default and offer **By Boundary** and **By Observed Status** as metadata-driven grouping options — zero catalog schema changes and zero hardcoded framework lists.
   - **Alternative:** Keep only **By Applicability** in M5.3 (simpler toolbar, no group-by switcher).
2. **Observed Status Label Refinement:**
   - **Recommended:** Rename `"Present"` → `"Observed in project"` and `"Multiple occurrences"` → `"Multiple copies observed"`, plus show an explicit non-activation disclaimer when observed skills exist.
   - **Alternative:** Keep existing `"Present"` label and only add the disclaimer text.
3. **Auto-Revealing Matching `Unknown` Skills During Search/Filter:**
   - **Recommended:** Keep `Unknown` collapsed by default, but automatically reveal matching `Unknown` skills while a search query or explicit filter (`Unknown` / `Selected` / `Observed` / `Needs review`) is active (restoring collapsed state when filters are cleared).
   - **Alternative:** Always require the user to manually click `Unknown (N)` even when searching.
