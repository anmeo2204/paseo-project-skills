# M1.1 — Foundation Planning

**Trạng thái:** Chờ phê duyệt triển khai M1.

M1 xây dựng nền tảng cho plugin `paseo-project-skills` trên Paseo Desktop và daemon 0.17.4. Plugin cài được từ checkout local, mở được qua sidebar, chọn được thư mục đích trên host, hiển thị trạng thái provider và lưu được cấu hình catalog.

Project-Skills là nguồn duy nhất của skill template. Khi đọc catalog, plugin phải dùng commit SHA hoặc resolve tag thành SHA trước. Thư mục chuẩn trong dự án là `.agents/skills/`. Agent chỉ quét và đề xuất. Plugin tính diff và ghi file sau khi người dùng duyệt. Roadmap sau M1 gồm M2 Read-only Scan & Recommendation, M3 Preview & Provider Adapters, M4 Safe Apply và M5 SLP Integration Pilot.

## 2. API đã xác minh

1. **Manifest và lifecycle.** Khai báo `id` và `requirements.paseo` trong `paseo-plugin.json`. Mỗi entrypoint `index.client.tsx` và `index.server.ts` default-export hàm đăng ký trả về cleanup. Server chạy trong subprocess với quyền của daemon và có thể trả về cleanup async. Compiler kiểm tra ranh giới `client/`, `server/` và `shared/`. [Paseo plugin guide](https://github.com/getpaseo/paseo/blob/v0.17.4/docs/plugins.md)
2. **Screen và sidebar.** Dùng `client.addScreen`, `client.addSidebarHeaderItem` và `SidebarRow` gọi `openScreen({ screenId })`, theo pattern trong `index.client.tsx` của SLP và Kanbanly. SDK client và RPC đi theo host của screen. [Paseo Plugin Reference](https://github.com/getpaseo/paseo/blob/v0.17.4/public-docs/plugins/reference.md#screens-and-sidebar-items)
3. **Typed RPC.** Khai báo `defineRpc({ name, input, output })` với Zod trong `shared/`. Nối `server.handle()` và `useRpc()`. Input được parse ở subprocess, output ở client. Handler nhận `{ paseo }` để gọi SDK. [Paseo `rpc.ts`](https://github.com/getpaseo/paseo/blob/v0.17.4/packages/plugin/src/rpc.ts)
4. **Project, workspace và cwd.** `projects.list()` liệt kê project đã đăng ký, kể cả project chưa có workspace hoạt động. `workspaces.list()` có phân trang. Dùng `projectRootPath` khi chọn project và `workspace.directory` khi chọn workspace, vì worktree có thể ở đường dẫn khác. `workspaces.open(cwd)` có thể tạo workspace nên luồng discovery chỉ dùng API list. Tham khảo `client/components/repository-folder-picker.tsx` của SLP và `server/service.ts` của Kanbanly. [Paseo SDK Reference](https://github.com/getpaseo/paseo/blob/v0.17.4/public-docs/sdk/reference.md#clientworkspaces)
5. **Folder picker.** App có **Open Project Folder**. Khảo sát API plugin công khai chưa tìm thấy primitive mở native folder picker. Kanbanly có browser riêng và native dialog chạy trên máy daemon trong `server/directories.ts`. Đề xuất M1 dùng danh sách project/workspace và ô nhập đường dẫn tuyệt đối, với RPC xác nhận thư mục bằng `realpath` và `stat` trên host. [Paseo `PaseoApi`](https://github.com/getpaseo/paseo/blob/v0.17.4/packages/client/src/index.ts#L590)
6. **Provider discovery.** `providers.snapshot({ cwd })` có thể trả trạng thái `loading`, `ready`, `unavailable` hoặc `error`. Daemon local báo `codex`, `cursor`, `kiro` và `antigravity` đều available. Tham khảo `client/use-provider-catalog.ts` của SLP để xử lý catalog đang tải. Khả năng đọc skill và nhu cầu sinh provider-specific rules hoặc derived skills được xác minh ở M3. [Paseo SDK Providers](https://github.com/getpaseo/paseo/blob/v0.17.4/public-docs/sdk/providers.md)
7. **Settings.** Dùng `defineSettings` với `scope: "host"` và schema version 1, `server.registerSettings`, `useSettings` và `client.addSettingsScreen`. Paseo lưu JSON theo installation và giữ giá trị qua reload. Đề xuất lưu `catalogRef` là tag hoặc SHA, với giá trị mặc định trống. [Paseo Settings Reference](https://github.com/getpaseo/paseo/blob/v0.17.4/public-docs/plugins/reference.md#persisted-values)
8. **Build, install, reload và test local.** Paseo tự compile TS/TSX. Chạy `npm ci`, `npm run typecheck`, rồi dùng CLI 0.17.4 chạy `plugin install "$PWD"`, `plugin ls` và `plugin logs paseo-project-skills`. Sau khi sửa, chạy `plugin reload paseo-project-skills`. Nếu reload thất bại, installation báo lỗi và cần sửa rồi reload lại. `plugin init` yêu cầu thư mục trống, nên áp dụng mẫu scaffold vào checkout hiện có `.git` và `paseo.json`. [Hướng dẫn directory source](https://github.com/getpaseo/paseo/blob/v0.17.4/docs/plugins.md#install-a-directory-source) · [CLI scaffold](https://github.com/getpaseo/paseo/blob/v0.17.4/packages/cli/src/commands/plugin/scaffold.ts)

## 3. Cấu trúc repository và dependencies

- **Root.** `paseo-plugin.json`, `package.json`, `package-lock.json`, `tsconfig.json`, hai entrypoint và `README.md` hướng dẫn chạy local.
- **`client/`.** Screen chọn đích, trạng thái provider và settings UI.
- **`server/`.** Handler xác nhận thư mục trên daemon host.
- **`shared/`.** RPC contract và settings schema.

Pin `@getpaseo/plugin@0.17.4` cùng các peer `@getpaseo/client` và `@getpaseo/protocol` ở cùng phiên bản để typecheck với host. Dùng React và React Native cho UI, TanStack Query cho trạng thái truy vấn, Zod cho RPC và settings, TypeScript cùng type definitions để kiểm tra local. Dùng Node built-ins cho filesystem. M1 dùng module do Paseo cung cấp và không cần database, MCP, bundler riêng hay runtime dependency vào SLP hoặc Kanbanly. [SDK package manifest](https://github.com/getpaseo/paseo/blob/v0.17.4/packages/plugin/package.json)

## 4. Implementation plan và nghiệm thu

1. **Scaffold và lifecycle.** Đăng ký một screen và một mục sidebar. Nghiệm thu bằng `npm ci`, typecheck và cài directory source với trạng thái `running`. Mở screen, reload hai lần và xác nhận sidebar chỉ có một mục, RPC vẫn hoạt động. Thử disable rồi enable để kiểm tra teardown.
2. **Chọn đích và typed RPC.** Nghiệm thu với Git root, worktree có đường dẫn khác root, thư mục non-Git và project chưa có workspace hoạt động. Kiểm tra đường dẫn hợp lệ, tương đối, không tồn tại và trỏ tới file. Khi đổi host, xóa lựa chọn cũ. Khi host offline, hiển thị lỗi tại chỗ.
3. **Provider và settings.** Kiểm tra snapshot nhận đúng cwd và UI phân biệt các trạng thái discovery. Xác minh bốn provider trên daemon local. Kiểm tra settings với giá trị mặc định trống, ref sai định dạng và ref hợp lệ. Lưu ref hợp lệ, reload rồi kiểm tra lại giá trị.
4. **Xác minh phạm vi read-only.** Đối chiếu trạng thái và nội dung thư mục thử nghiệm trước và sau smoke test. Không tạo `.agents/skills/`, mở agent, tải catalog hay ghi vào dự án đích. Giữ thao tác lưu settings trong cơ chế lưu trữ của Paseo.

## 5. Quyết định chờ phê duyệt

- **Baseline.** Khai báo `requirements.paseo: ">=0.17.4"` và nghiệm thu M1 trên Desktop/daemon 0.17.4.
- **Chọn đích.** Dùng project/workspace đã đăng ký hoặc nhập đường dẫn tuyệt đối. Hiển thị rõ host và đường dẫn thực tế, đặc biệt khi chọn worktree. Hoãn browser tùy biến và native dialog.
- **Catalog.** Cố định nguồn Project-Skills và lưu `catalogRef` theo host. Để mặc định trống cho đến khi có tag hoặc SHA được duyệt. M2 resolve tag thành SHA trước khi đọc.

Khảo sát đã kiểm tra source và trạng thái daemon bằng thao tác chỉ đọc. Việc cài, reload và smoke test plugin mới thuộc giai đoạn triển khai sau phê duyệt.
