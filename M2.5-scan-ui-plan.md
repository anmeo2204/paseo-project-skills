## 3. User interaction flow

1. Chọn host trên Paseo, chọn project root, workspace hoặc path. Chờ validation và hiển thị canonical directory.
2. Chọn một hoặc nhiều Target Providers nếu đã biết đích. Có thể để trống và quyết định sau khi xem skill. Dùng catalog ref đã lưu trên host. Draft chưa Save không thay catalog dùng cho lần chạy.
3. Nhấn **Scan & Recommend**. Một lượt gọi `catalog.load` lấy description, resolved SHA và settings revision. Khi response còn thuộc đúng attempt và saved revision, mở đúng một `recommendation.evaluate` với `requestId`, `canonicalDirectory`, `expectedCatalogSha` và `expectedSettingsRevision`. Catalog preflight chỉ đọc catalog. Project scan diễn ra bên trong recommendation subscription.
4. Ghép result items với catalog descriptors theo Skill ID sau khi kiểm tra host, path, request, settings revision, commit SHA và source. Hiển thị result khi provenance khớp. Nếu tag di chuyển giữa preflight và evaluation, hiển thị catalog changed và cho phép chạy lại theo yêu cầu.
5. Mở chi tiết để xem evidence hoặc inventory. Chọn skill thủ công hay dùng bulk controls. Khi selection thay đổi, cập nhật selected count ngay trên screen.

M2.5 không gọi `target.scan` từ flow này. Route vẫn dùng độc lập cho tooling và regression smoke. Mỗi lần người dùng yêu cầu scan mới sẽ resolve lại catalog, kể cả khi ref vẫn là cùng một tag.

## 4. Component reuse strategy

- Giữ source registration, sidebar ID, `TargetPicker`, validation query và `ConnectionCheck`. Tiếp tục dùng `Section`, `Detail`, `Action`, `Input` và host `ScrollView`, `Modal`, `Icon`. Dùng React state/ref cho flow và selection. TanStack Query tiếp tục phục vụ query hiện có.
- Đọc `useSettings(catalogSettings)` một lần trong host screen và truyền state/actions cho `CatalogSection`. Giữ editor draft tách khỏi saved revision. UI invalidate theo thay đổi settings đã lưu hoặc host push, không theo mỗi lần gõ.
- Giữ provider rows và query discovery. Đưa checkbox intent thành controlled props. Dùng availability để hiển thị trạng thái, giữ selection khi discovery loading, unavailable hoặc error.
- Tách recommendation view khỏi lifecycle để test độc lập. Dùng `useRpc(catalogLoadRpc)` theo click và `useSubscription` trong component chỉ được mount khi attempt đủ preconditions. Không cần global store hoặc caching layer mới.

## 5. UI state model

Giữ target validation, settings, attempt và selection ở scope của host screen. Attempt có identity bất biến và phase. Selection chỉ tồn tại khi có accepted `ready` hoặc `partial` result. Render state có thứ tự ưu tiên offline → target/settings gates → attempt status.

| Trạng thái | UI và transition |
| --- | --- |
| No project selected / validating | Show picker và validation feedback. Scan chỉ bật khi canonical target đã có. |
| Catalog not configured | Hướng người dùng đến editor và **Save revision**. Tách rõ loading/invalid/read error của host settings. |
| Catalog loading | Sau click, hiển thị “Loading skill catalog…” và **Cancel**. Lượt `catalog.load` đang chạy có thể kết thúc trên daemon sau khi UI đã bỏ attempt. |
| Scanning/recommending | Hiển thị “Scanning project and evaluating skills…” và **Cancel**. Backend trả terminal event, nên chỉ dùng trạng thái đang xử lý, không hiển thị phần trăm. |
| Ready | Hiển thị identity, counts và kết quả. Selection ban đầu rỗng. |
| Partial | Giữ các positive matches. Phân biệt scan chưa đầy đủ với sidecar invalid/unsupported. Ví dụ “Một số thư mục hoặc tín hiệu chưa được kiểm tra hết. Kết quả có thể thiếu.” Mở warnings để xem code đã diễn giải và relative path nếu có. |
| Empty positive matches | Khi Recommended và Optional đều rỗng, giải thích evidence/rules chưa đủ và vẫn cho mở Unknown. Với legacy catalog, ghi rõ revision thiếu applicability metadata. |
| Error | Ánh xạ typed codes sang hướng xử lý. Ví dụ lỗi SSH/network → kiểm tra host hoặc thử lại. `busy` → đợi request cũ kết thúc rồi chạy lại. `target_changed` → chọn/validate lại. `limit_exceeded` → giải thích giới hạn quét/kết quả. `invalid_evidence` và transport/parse failure dùng thông báo chung. Không render stderr hoặc thông báo parser thô. |
| Offline | Giữ thông điệp active host offline, ẩn kết quả và khóa flow. Reconnect trả về trạng thái chọn target theo Foundation, chờ click mới. |
| Cancelled | Hiện “Scan cancelled” và cho chạy mới. Đây là UI state sau release/ignore, không đợi server gửi event cancelled. |
| Stale result | Khi settings/pin thay đổi, ẩn items và selection, giữ thông báo cùng hành động chạy lại. Khi đổi host hoặc target, bỏ toàn bộ payload cũ và hiển thị identity mới ngay. |

## 6. Recommendation presentation

**Recommended** mở mặc định. **Optional** có nhóm riêng và mở khi có mục. **Unknown** mặc định gấp, hiện số lượng và có thể mở để chọn. Dùng thứ tự ổn định theo Skill ID trong từng nhóm. Contract giữ `not_applicable` cho tương lai, production v1 không phát verdict này. Một payload ngoài semantics v1 phải vào lỗi tương thích, tránh đổi nghĩa khi render.

- Mỗi hàng hiển thị Skill ID, description từ catalog cùng SHA, verdict project fit, inventory state và reason tóm tắt. Recommended mô tả sự phù hợp với project evidence. Phần đầu kết quả ghi task applicability chưa được đánh giá. Không có confidence score.
- Dùng reason code để hiện câu ngắn cho reusable workflow, strong project match, thiếu evidence nâng mức, thiếu evidence nói chung hoặc sidecar thiếu/lỗi/chưa hỗ trợ. Với nhiều boundary, tóm tắt số boundary khớp và mở chi tiết từng boundary, verdict và reason. Hiển thị `.` là “Project root”.
- Chi tiết evidence tra `project_evidence` bằng ID để hiển thị relative path, ref kind và selector nếu có. Với `catalog_file`, hiển thị path và blob SHA, kèm pinned catalog ở header. Với `scan_coverage`, hiển thị coverage liên quan. Evidence là dữ liệu để đọc, không tự mở file trên host.
- Inventory thể hiện `present`, `multiple_occurrences`, `not_observed` như “Chưa thấy trong scan”, và `unknown`. Khi mở, hiện layout, relative path, boundary, confirmed/candidate, directory/declared ID nếu lệch, và flags mismatch, possible customization, malformed hoặc unreadable. Không diễn giải occurrence là provider activation hay quyền overwrite.

**Technology summary.** Recommendation v1 mang coverage, boundary paths của positive matches, reasons và tập refs đã sử dụng. Nó không chứa `ProjectEvidence.facts`, danh sách đầy đủ boundaries hoặc direct/inferred basis của từng technology. M2.5 hiển thị **evidence dùng cho đề xuất** và **boundary matches**. Không suy stack từ tên skill, basename hoặc `coverage.unknown`. Đề xuất giữ nguyên wire contract. Nếu review yêu cầu summary stack riêng, extension nhỏ nhất là projection server của các fact language/framework đã có trong cùng scan, chỉ gồm `boundaryPath`, `kind`, `key`, `basis`, dedupe/sort và tính vào response budget 512 KiB. Vì result v1 strict, khi triển khai projection cần version/opt-in có tương thích và giữ đường v1 cho client cũ. [Result contract](shared/recommendation.ts), [Scanner evidence](shared/project-evidence.ts)

## 7. Selection semantics

| Hành động | Quy tắc |
| --- | --- |
| Manual selection | Checkbox ghi stable Skill ID, cho cả Recommended, Optional, Unknown và các skill có occurrence. Group collapse/expand không đổi selection. |
| Select Recommended | Chỉ khi người dùng nhấn, thêm toàn bộ Recommended của active result vào selection. Giữ những ID người dùng đã chọn ở nhóm khác. |
| Clear Selection | Xóa toàn bộ Skill IDs, giữ Target Providers. |
| Scan/Rescan | Mỗi attempt mới bắt đầu với selection rỗng và bỏ results cũ. Không carry-over, kể cả SHA và target giống nhau, vì evidence hoặc inventory có thể đổi. Cancel/error giữ selection rỗng. |
| Target/host/settings thay đổi | Bỏ result và selection, invalidate attempt trước khi render scope mới. Khi settings đổi, provider intent có thể giữ cho cùng host/target. Khi đổi host/target, reset cả provider intent. |
| Provider thay đổi | Chỉ sửa installation intent đang có, giữ result và skill selection. |

Selection là memory-only theo host installation, canonical target, pinned SHA, settings revision và accepted request identity. Thay đổi ref, settings revision hoặc scope làm selection mất hiệu lực. M2.5 không dò thay đổi ngoài filesystem giữa các lần scan. Nhận diện stale catalog tag khi resolve lần kế tiếp, không poll theo thời gian.

## 8. Provider selection semantics

- **Target Provider** là ý định đích cài đặt sau này. Giữ bốn options hiện có và cho phép chọn dù discovery đang loading/unavailable/error. State ban đầu rỗng. Scan chạy với 0, 1 hoặc nhiều target providers.
- **Provider runtime availability** là snapshot theo host và canonical cwd. Các states hỗ trợ người dùng cân nhắc, không filter verdict, không bỏ selection khi runtime status đổi. Giữ retry và polling loading có điều kiện đang dùng, chỉ khi picker section mount. Scan flow không thêm polling.
- **AI execution eligibility** thuộc M2.3 và phụ thuộc profile đã xác minh. M2.5 không chạy preflight, liệt kê model, tạo agent/session hoặc gửi inference request. Provider availability không đồng nghĩa với skill installation support. [M2.3 verification](M2.3-completion-report.md)

## 9. Lifecycle và isolation

1. Dùng installation host context, host key, screen instance và target selection generation của Foundation. Tăng generation khi người dùng chọn target kể cả cùng path. Mỗi click/retry cấp request ID mới hợp schema, giữ canonical directory và settings revision theo attempt.
2. Sau catalog preflight, kiểm tra identity đang active và token trước mọi state update. Kiểm tra catalog reply revision, pinned SHA và source. Mount child subscription chỉ khi preconditions đã sẵn sàng. Truyền input ổn định trong lifetime của child. SDK 0.17.4 `useSubscription` tự subscribe khi mount, resubscribe khi input đổi và release trong effect cleanup.
3. Guard callback và completion theo mounted scope, current attempt, host, target generation, saved settings revision và request ID. Với result, so thêm canonical directory, source và commit SHA. Vì SDK gọi callback mới nhất, handler phải kiểm tra ID event, không chỉ closure hiện hành. Đánh dấu attempt settled trước khi publish vào UI và tháo child ngay khi nhận terminal event. Transport đóng thiếu terminal event thành lỗi có thể retry, trừ khi đã release chủ động.
4. Cancel, host/target switch, revision đổi, offline và unmount/reload đều invalidate token và bỏ child. Catalog RPC không có cancel handle từ `useRpc`, vì vậy bỏ late promise. Recommendation release chuyển abort qua transport đến daemon. Nếu user retry khi slot trước chưa settle, hiển thị typed `busy`. Không tự retry hoặc dispose loader từ screen.
5. `useSettings` của Desktop nhận invalidate khi host settings đổi. Daemon cũng revalidate settings trước publish. Khi screen thấy host mất kết nối, tháo subscription và bỏ attempt. Host transport có hỗ trợ replay subscription còn mở khi reconnect, nên test phải chứng minh UI release đúng và chặn late events kể cả trong cửa sổ reconnect. Screen không tạo attempt mới trên reconnect. A → B → A vẫn có generation và request ID riêng, tránh chấp nhận kết quả của lượt A đầu.

- Không có blocker để review hoặc bắt đầu implementation sau khi duyệt. Desktop lifecycle của UI mới và multi-host thật chưa được xác minh. Record rõ PASS/FAIL/BLOCKED/NOT TESTED khi nghiệm thu.
- Duyệt các quyết định chính gồm một screen, Target Providers tùy chọn và độc lập runtime availability, selection rỗng mỗi lần rescan, giữ contract v1, chỉ hiển thị evidence đã dùng và boundary matches.
- Mốc hoàn tất M2.5 là UI đọc và chọn skill trên active host, kết quả có provenance hợp lệ, 70 regression tests tiếp tục PASS và Desktop smoke trên 0.17.5. Preview, provider adapters, Safe Apply và AI-assisted flow thuộc các milestone sau.
